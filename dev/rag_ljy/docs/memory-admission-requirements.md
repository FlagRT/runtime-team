# 显存感知RAG准入的验收要求

本文件记录最终目标；当前结果以根目录[status.md](../status.md)及原始实验文件为准。不能把目标清单当作完成声明。

- 请求实际执行vLLM embedding、Milvus或Elasticsearch检索、Transformers rerank。
- 在接收进模型/阶段队列之前，依据请求的实际token、有效batch、dtype、模型结构及执行配置估算全链路新增峰值；不得退回固定2GiB。
- 检索前对候选文档长度采用有执行约束的上界，检索后对实际padding形状复核。当前部署上限640文档token；现有6,543块离线重建核对最大578，不影响当前语料。未来超限文档会截断并记录，不能宣称结果完全不受影响。
- 常驻模型/引擎池已在实测占用中，不重复计入新增估算；不同请求预留仍须累加，保留至完成后的新采样。
- 唯一指标来自`device-context.runtime.memory_stats()`：`实测已用 ≥ 总显存×85%`暂停，暂停后仅在实测占用≤75%时恢复。每次采样即更新滞回状态；请求预留预算不参与水位判定。
- 每个新请求还须满足`实测空闲−未释放预留−该请求估算≥5GiB`。预算不足不冒充高水位滞回。
- 无固定8请求入口限制。正常压力暂停只拒绝新请求，已接收工作继续排空；拒绝返回503和Retry-After，不自动放回内部队列。
- 每个forward前检查最新device-context读数及实际输入形状。可缩小执行batch、释放未使用缓存后复核，不能靠试分配大块显存验证能否容纳。
- 对过期/失败/不可信读数、未知执行配置、缺失或无效估算采取拒绝。记录所有准入决策。
- 按模型/软件/执行配置指纹隔离实测数据。记录估算值、Torch分配器峰值、设备总量采样及并发归因限制；覆盖独立holdout前不能把保守公式称为已校准上界。发现低估应停止新准入并重校准。
- 在突发、错峰、持续三种到达模式中，分别以真实模型请求达到实测85%以上，并验证拒绝、75%～85%滞回、≤75%恢复和已接收请求完成。
- 禁止额外显存填充、降低阈值或扩大常驻模型池冒充请求压力；若保护余量被突破、未达阈值、没有中间窗口或任何模式未完成，报告未通过。
- 证据固定保存到外部experiments目录，包含代码/模型/配置、输入、实际时间线、HTTP结果及复现命令；请求数量、显存占用、记账预算、计算利用率分别报告。

## 当前实现与剩余工作

已实现并部署动态估算、逐请求预留、执行前检查、估算预览`POST /memory/estimate`、执行配置核对及逐forward分配器峰值观测。支持范围目前是同容器可验证的本地vLLM Qwen3 embedding与Transformers Qwen3 reranker；其他配置会要求验证，不静默套用假设。

当前为`qwen3-execution-v3`。核对真实融合attention算子后按层临时量与输出层的实际生命周期估算，使用1.15系数、每阶段512MiB工作区及单独分配器增长预算。对已在实测占用中的完全闲置缓存段，可给予独占增量抵扣；缓存释放时将抵扣补入请求预留，避免重复使用新增空闲空间。未确认融合算子时使用更保守的dense公式。

2,707条历史forward的回顾性复核没有低估，最大实测/估算约0.962；这不证明任意输入及配置的通用上界，接口仍明确标记`analytical_uncalibrated`。独立冷启动的三种到达模式均已通过真实高位/中间滞回/低位恢复验收，范围与证据见[status.md](../status.md)。早期450次请求只达到44.629%、旧97.17%保护线失败及中间窗口缺失记录均保留，不算通过。

监测使用独立进程调用同一个`device-context.runtime.memory_stats()`，避免本模型分配器锁阻塞采样；观察进程不分配压力tensor，其持久上下文开销计入空载基线。采样年龄包括读取耗时。服务的正常闲置压力回收使用公开allocator接口，并释放Python GIL，使回收期间仍能处理拒绝及观测滞回。

估算失效或执行保护无法安排安全的单项forward属于需要报告的异常，不应把这类已接收请求的失败算作“正常压力下全部继续完成”。
