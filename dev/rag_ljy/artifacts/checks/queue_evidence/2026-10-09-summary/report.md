# RAG 在线多请求与阶段队列验证摘要

测试日期：2026-10-09（北京时间）。环境：物理 NPU 7；Milvus；vLLM embedding；Transformers 精排。使用固定 NFCorpus 50 条查询中的前 8 条，超限场景重复第一条作为第 9 个请求。

| 验证项 | 实测结果 |
|---|---|
| 同时到达 | 8/8 成功，结果及排序与串行参考一致 |
| 错峰到达（间隔20ms） | 8/8 成功，结果及排序与串行参考一致 |
| 9请求超限突发 | 8个成功、1个预期503拒绝，Retry-After=1 |
| 超限后恢复 | 1/1 成功，全部队列及在途请求归零 |
| 独立阶段推进 | 33个成功请求三阶段记录完整、依赖顺序正确；观察到60对跨请求阶段区间重叠 |
| 队列容量约束 | 525次采样未超限；在途峰值8，三个阶段等待峰值分别为6、1、7 |
| 调度/API测试 | 22项全部通过，覆盖背压、取消、错误隔离及恢复 |
| 已有双库完整链路测试 | 同一50查询×Milvus/Elasticsearch×两种模式，200/200成功；两库各50/50结果一致 |

本轮34次HTTP调用：33次成功、1次预期超限拒绝。分数一致性容差：相对1e-4、绝对1e-6。

独立推进实例：PLAIN-1141在59.29ms已进入精排，整组最后一个请求的embedding在369.91ms才结束，无需等待整组完成上一阶段。

当前实现为请求数量准入控制与三个独立有界队列；**内存水位准入尚未实现**。上述重叠是服务端阶段区间重叠，不证明底层NPU kernel同时执行或vLLM合并forward batch，也不代表吞吐提升。
