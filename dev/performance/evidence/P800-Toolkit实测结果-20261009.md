# P800 Toolkit 实测结果

**12 个 Case 的测量、监控和诊断通过；20 个重复组不稳定，尚未取得性能资格。** 本文是人工整理的实测摘要，不是完整原始证据包。复核日期：2026-11-05，未重新运行设备负载。

## 测试条件

| 项目 | 条件 |
|---|---|
| 运行 ID | `20261009T014046Z-0cb914bb` |
| 测量代码 | `d356e374`；独立 C++ 程序调用 XBLAS / XRE，不复用 Base 的 PyTorch workload |
| 镜像 | `flagtree-xpu3.6-py310-torch2.9.0-flaggems-main-dev:202608`，P800 候选栈 |
| 设备与规模 | 单机两卡；矩阵 8192³，搬运 512 MiB，P2P 带宽 256 MiB、时延 64 KiB |
| 重复协议 | 每点 5 次独立进程；计时目标至少 50 个样本和 15 秒，监控开启 |

## 实测结果

| 检查 | 结果 |
|---|---|
| 覆盖 | 12/12 Case，97 个逻辑点 × 5 次，共 485 个目标；475 个计时目标、10 个容量查询 |
| 测量 / 监控 / 诊断 | 均为 passed；最短计时窗口 15.00000004 秒，每目标每设备至少 29 个监控样本 |
| 重复稳定性 | 101 个指标重复组：81 stable-observed，20 unstable；指标组数与逻辑点数不是同一分母 |
| 清理 | cleanup / postflight passed，租约释放 |
| 资格 | `not-qualified`，runtime 为 candidate / `validated:false` |

| 指标 | 本轮观测值 | 口径 |
|---|---|---|
| FP32 / FP16 / BF16 | 约 118.5 / 269.3 / 118.9 TFLOPS | XBLAS 原生 GEMM |
| INT8 | 两卡约 476.7 / 489.1 TOPS | 两张卡的重复组分别统计 |
| D2D runtime copy | 两卡约 11.2 / 11.5 GB/s | 按载荷 1× 计算 |
| D2D XBLAS Scopy | 两卡约 2138.8 / 2138.6 GB/s | 按读写 2× 计算，不能与上一行直接比倍率 |
| P2P | 单向约 20.87、并发双向约 20.59 GB/s；64 KiB 时延 18,459 ns | 仅所测设备对与协议，不外推全部设备对 |

## 保留的问题

| 问题 | 影响与后续 |
|---|---|
| 20 个不稳定组 | 17 组 pinned H2D/D2H、3 组 1 MiB D2H pageable 时延；不称“全部稳定通过” |
| pinned async 整块错误 | 历史返回 -999；本协议使用 1 MiB 分块并统一等待，不能称单次整块异步调用 |
| BF16 性能差距 | Base 的 XMLIR 快路径不等于 Toolkit XBLAS 路径；不以 Base 的约 223.9 TFLOPS 替换本轮结果 |
| 环境迁移 | 本轮为历史镜像结果；新 FlagRT v2 镜像 smoke 不继承本轮资格 |
