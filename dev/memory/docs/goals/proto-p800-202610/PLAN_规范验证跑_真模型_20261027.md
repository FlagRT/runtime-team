## 1. 池档位阶梯（本轮相对先例的主要新设计，单列一节）

每档跑**完整腿链**（§3），两档间切换 = 重启重挂（引擎史重置，如实记录）。执行顺序：**先 64GiB 锁定档，后自然池档**——锁定档 P 腿第一时间给出与先例 466,032 tok 的可比校验，新仓漂移最早暴露在锚点档。

| 档 | 配置 | 存在理由（G3 重点检查项） |
|---|---|---|
| 档 A：64GiB 锁定档 | kv-cache-memory-bytes=**64GiB**（gmu 0.8） | **先例可比锚点**：与 2026-10-25 先例（466,032 tok @ ≈145KiB/tok）同口径，检验新仓重挂载后引擎行为是否漂移；一切跨日对照只在此档内成立。**仅该档内与先例 466,032 tok 分母可比，不得跨档并列**（数字五要素·池口径） |
| 档 B：自然池档 | **不锁 kv-cache-memory-bytes**（gmu 0.8），部署真实态 | **G2/G4 口径的部署真实态**：回答"按协议固定表默认部署，用户实际拿到多大池、什么性能"；无锁定值干预下的引擎派生池是自然档独有的测量对象 |
| 中间档 | **不加** | 两锚点预算同源：gmu 0.8 预算 ≈0.8×95.97≈76.8 GiB，减权重 15.63 GiB 后派生余量 ≈59–61 GiB（引擎工作区未单列，先例未测），与 64 GiB 锁定值相差约 6–10%——两档之间不存在已知行为边界；每档池内 B 四档阶梯（25→110%）已各自覆盖本档饱和边界（含 100% 悬崖）。更高锁定值（>64GiB）将超出 gmu 0.8 预算、须改 gmu，即偏离 §2 协议固定表 |

**中间档升级条件（预注册决策规则）**：若 P 腿实测两档池 tok 相差 >15%（上述预算推算被证伪、阶梯跨度大于设计），当日**不自行加档**，升级请示后按指示处理（操作层新增腿须声明）。

## 3. 腿本（每档池内依次执行；每腿判据开机前写定，可判定、不依赖主观措辞）

| 腿 | 定档 | 支持的结论 | 有效判据（不满足 = 无效，不入正文） |
|---|---|---|---|
| P 池画像 | 零生成请求；就绪后 +2/+5/+10min 采样稳态 HBM；**梯度逐档做池画像** | 本档池物理常数（本档所有腿推导的分母） | 池 tok 必须取自引擎日志原文行（"GPU KV cache size"），并与块常数交叉验证（bytes/tok ≈145KiB 量级口径）；缺失该行不得出池数字 |
| S1 prefill | 256/1024/3072 tok 三档 ×3 轮全计，max_tokens=1；**每轮冷 prompt**（请求号 i=r×7919+L 唯一）；/tokenize 校准 | 纯 prefill 时延曲线（**不回答吞吐**） | 任一档输出 >1 tok 即该档无效（decode 混入）；prompt 实测 tok 偏离目标 >10% 无效 |
| S2 decode | 输入 256 tok，输出 512 tok；**暖 1 测 3** | 单流 decode 稳态速度 | completion_tokens ≥128 才入 decode 结论；报中位数 + 最差值 |
| B 四档 | 并发数 = round(目标池占比 × **本档**池tok ÷ 4096)（F=4096 满长口径），占比 **25/50/90/110%**；prompt 目标 **3840 tok**（=4096−max_tokens 128−余量 128，余量条款为判据）；max_tokens=128；每档 2 轮取第 2 轮（首轮 sanity） | 容量曲线 + 饱和分界线 | 每档须同时报池利用率峰值（**比 token 不比百分比**）；<30% 档只标"未饱和参考"，不得用于容量/饱和结论；"饱和/排队"结论须 capacity waiting>0 或驱逐>0，否则视为没压到、加码重测；每请求输出 <128 tok 只进排队/容量结论、不进 decode 结论 |
| cost / expand | cost = B 25%/50% 档；expand = B 110% 档 | cost 回答代价；expand 回答收益 | cost：OFF/ON 差值 ≈0——判据是"**无代价**"非"无 DMA"（connector store 策略积极，先例 24% util 仍有 store DMA）；expand：OFF 侧必须出现 capacity waiting>0（或驱逐>0）；ON 侧必须有 DMA 计数（**store/load 分开**）+ 单批块数 + **host RSS 起止** + **完成归还检查**，且 DMA 计数与块数账互洽——缺任一，"收益"结论无效 |
| L load 侧 DMA 补腿（本轮新增） | ON 引擎 B 110% 档第 2 轮完成（池满载驱逐-store 已发生）后，**同引擎史内**重放该档唯一 prompt 批 2 轮（同 i 同内容）；OFF 引擎对称重放 2 轮 | load（host→device 回迁）路径的**首个**功能+代价测量（先例 656store+仅 2load / 846store+3load，load 侧为真实缺口） | ON 侧 load DMA 计数 >0 且与块数账互洽 + host RSS 起止 + 完成归还检查；重放输出与本批首测输出（同引擎 reference）逐字全等；代价 = 重放完工时间 OFF/ON 差值（n≥2 才报差值）。未触发（load 计数=0）→ 本腿标"未触发·无效"，调整触发方式重试属操作层偏离须声明 |
| R 正确性 | canonical 输出对照 + recall_output_equal + cancel 后资源归零 | 功能正确性验收（对照腿必过） | 三方（OFF/ON/reference 可用时）逐字全等；cancel 后资源归零 |

**腿序（判据的一部分）**：P → S1 → S2 → B（25→110% 递增）→ cost → expand → L → R，轻→重串行；重载饱和腿之后不得接测轻量腿（先例：S1 紧跟 c125 满载腿，256tok TTFT 8.2s vs 1024tok 2.2s 倒挂）。

## 4. 并发与执行纪律备注（用户拍板七条，照录不扩写新判据）

1. 空闲/占用唯一真值=容器内 torch.cuda.mem_get_info，xpu-smi 双向会骗（报 0 实隐 53.6G、报 65G 实为空卡）——占卡与独占判定禁用 xpu-smi 当判据（PROFILE-PROTOCOL §2 三次说谎凭证）。
2. 共卡污染病态：4B 上午 0.8 tok/s=共卡污染 17×、独占复测 13.4——测定起止各记一次邻卡状态，独占判定写入锚点；邻居早上线多卡扫场（曾同握 4 张"空闲"卡），傍晚 free 96→41.08GiB 仅 4 分钟。
3. 并发档位由池除法推导（25/50/90/110%），禁拍脑賦（c64 仅占池 6% 反例）；prompt 长度余量=max_model_len−max_tokens−128 tok（压线 400，c28 首跑 19/28 请求 400 凭证）。
4. FL 插件版本三元组病态：vllm-plugin-fl 0.0.0 vs 0.2.0 行为差异巨大（启动门槛修复、decode 未修）——锚点必写版本+短 hash；connector store 策略积极（24% util 仍有 store DMA），cost 腿判据是"无代价"非"无 DMA"。
5. 腿序纪律：重载饱和腿后不得接测轻量腿（S1 紧跟 c125 出现 TTFT 8.2s vs 2.2s 倒挂）。
6. TP=1 单卡口径、单实例 API server；max_num_seqs/chunked prefill/prefix caching 记录实际生效值。
7. 容器内 nohup 重定向写 exec 外层、长等待本地 sleep+短查询轮询（P800 SSH 纪律）。

## 5. 容器、占卡与真值纪律

- 容器沿用 **mem-profile-p800**（绑 xpu5）；`docker restart` 重挂新仓 /data1/chenyuanxin/memory-manager；**不占卡时 docker stop 让卡**。
- gmu 闸遵守宿主机规则；实际足迹 ≪ gmu×total 时降档合法（写明）。

## 7. 预注册预期（跑前写定，防事后挑数；均为预期非结论）

1. 64GiB 锁定档池 tok = **466,032 量级**（引擎日志原文；先例同配置）——若新仓重挂载导致漂移，如实记录，作为"新仓 vs 先例"的第一发现，不修饰。
2. 自然池档池 tok < 锁定档，推算 **≈42–44 万 tok 量级**（0.8×95.97 − 权重 15.63 − 引擎工作区；工作区先例未单列，故为区间）——推算仅作预期，判据 = 引擎日志原文 + 块常数交叉验证。
3. 锁定档 S2 OFF ~**13.8–13.9 tok/s** 量级（先例 13.90，跨日复现）；ON 同量级（先例差 ≤1.2%）。
4. 锁定档 B：c25/c50 未饱和；c90 逼近；c110 OFF 侧 capacity waiting>0；饱和档聚合吞吐悬崖复现（先例 c102 ≈90 tok/s → c125 ≈11 tok/s）。ON 侧收益形态开放（先例为完工 −17%，非消除排队）——按实测记录，不套先例结论。
5. expand/L 档 ON 侧 DMA store>0 且 **load>0**——本轮目标是把先例"store 多、load 近乎为零"的缺口补成 load 有效测量。
6. JIT 首跑数值漂移可能复现（先例 ON r1/r2 sha 不一致、warm 后收敛）——离群轮保留并说明，不悄悄丢弃。
7. 自然池档数字只与本档内比；与锁定档、与先例**均不并列**（池口径不同 = 五要素不全，分开各表）。
