# 910C 规范验证跑结果（vllm-ascend 栈，2026-10-25）

> PROFILE-PROTOCOL v0.3 首次跨芯执行。环境：910C 节点（davinci4 基线）（容器 mem-profile-910c，
> 真值 60.9/61.3 GiB free，独占）、OneRec-8B、vLLM 0.20.2 + vllm-ascend v0.20.2rc1、
> TP=1、4096、eager、gmu0.9；池 **285,568 tok / 69.72×**（引擎日志原文，与 10-12 基线
> 逐字一致）。对照项=kv-transfer-config 有无（**offload.npu_offload，memory-manager
> 新仓路径首次真机加载**：register COMPLETED、swap→NpuSimpleCPUOffloadWorker、
> pinned）。Host 池 8 GiB。校准 2.9004 tok/词（与 P800 同 tokenizer 同值 ✓）。
> 档位 c=17/35/63/77（池 25/50/90/110%）。FL 栈不跑本规范（decode 16 s/token，
> S2 一轮 5.5 min，引用 10-25 已有 0.2.0 补测数据）。
> 跑前声明沿用 P800 版判据（档位常数按 910C 池重推）。

## 1. S 腿

| 腿 | OFF | ON | Δ |
|---|---|---|---|
| S1 prefill 3072 tok | **0.23 s（13,300 tok/s）** | 0.23 s | 逐毫秒一致 |
| S2 decode 512 tok（r2-r4 中位） | **25.96 tok/s** | 25.13 tok/s | **−3.2%** |

（P800 对照：prefill 482 tok/s、S2 差 −1.2%。910C prefill 快 28×。）

## 2. B 档位（第二轮报告口径，第一轮见数据文件）

| 档 | util% | OFF wall / agg | ON wall / agg | Δagg |
|---|---|---|---|---|
| c17（24%） | 23.6 | 5.6s / 389 tok/s | 7.2s / 300 | −23% |
| c35（49%） | 48.7 | 5.9s / 763 | 7.5s / 598 | −22% |
| c63（90%） | 87.6 | 7.5s / 1070 | 9.3s / 867 | −19% |
| c77（110%） | 92.6 | 29.6s / 333 | 29.8s / 330 | ≈0 |

- **OFF 基线近线性扩展**（389→763→1070），c77 温和降速（3×，对比昆仑满载 8× 崩）
  ——**满载病态是昆仑栈特有的，vllm-ascend 栈没有**。
- **npu_offload 的代价形态与 xpu_offload 不同**：昆仑非饱和零代价（≤2.6%）；
  910C 非饱和 −19~23%（warm 批量档）/ −3.2%（单流），饱和档反而无差。
  机制假说：ascend 步时更短（~44ms vs 72ms），connector 每步固定开销
  （event 轮询/队列检查）占比放大；饱和档 compute 主导开销被掩盖。
  → **报 W3 数字时必须按栈分开**，10-14 的"decode 代价 7-8%"与本次 −3.2%/−20%
  是不同负载形态下的同一 connector。
- c77 两轮 util 98.7%→92.6%、capW 6→58：cache 状态携带效应（r1 的块被 r2 的
  prefix 命中，admission 形态改变）——饱和档轮间不可比，两轮都报。

## 3. DMA 与正确性

- **ON 窗口 DMA：359 store（中位 16 块、单次最大 297 块、合计 11,585 块）+ 0 load**。
  store 同样在非饱和档发生（活跃 store 策略跨芯一致）；0 load = 本轮负载形态
  （一次性唯一 prompt、无重访）不需要召回，属预期。
- **正确性：S2 四轮 + B 各档输出 sha1 OFF=ON 全等（f6a4e91e55…）**——比 P800 还干净
  （P800 的 ON r1/r2 有 JIT 首跑数值漂移，ascend 栈没有）。

## 4. 规范跨芯结论

- 驱动/判据零修改可移植（校准、池推导档位、有效判据全部照跑）；
  池常数、档位常数按栈重推即可——**模板可移植性从"昆仑一栈验证"升级为"双芯验证"**。
- capW 谜题添证：c63-r1 capW=12（87.6% util）而 r2 同 util capW=0——
  与 P800 的 r1/r2 形态一致，**支持"capacity reason 含 prefill 预算等待"假说**
  （r1 真预填按预算分批进场，r2 缓存命中秒进）。待源码最终确认。
- 两芯代价差异本身是交付物：memory-manager 的 offload README 需按栈写明代价形态。
