# 平台开发纪律（自 FlagScheduler AGENTS.md 平台相关部分迁出整理）

> 代码开发的行为契约（兼容键硬隔离、结果恰好一次回填等）仍在
> FlagScheduler 仓 `AGENTS.md`；本文只收**平台/设备相关**的纪律与环境事实。

## 真机运行红线

- 启动容器或占用加速卡前，**必须**先在宿主运行设备检查（昆仑芯
  `xpu-smi` / 昇腾 `npu-smi info`）确认目标卡空闲（0% 利用率 / 0MiB 显存），
  并核对是否有他人容器/进程在跑。
- P800-A 配额卡：**宿主 2、3、7 号**，空闲时可用；其余卡属于他人，不得占用。
- 设备冲突时核对归属，避免影响他人的容器或进程；不做任何需要 root 的
  驱动级操作（设备重置可能杀掉他人多日任务——两起驱动故障期间均未越界）。
- 平台事故与规避（如 P800 的 bge-reranker 加载即崩、驱动卡死两起）记录在
  对应平台 README 的"已知平台事故"节，新机器接入前必读。

## 结果记录纪律

- 真机跑出的结果 JSON → 本分支 `platforms/<平台>/data/`
- 排查/缺陷分析 → `platforms/<平台>/investigation/`
- 一次性探针脚本与原始日志 → `platforms/<平台>/raw/`（证据链完整性）
- 进度与待办 → `platforms/<平台>/progress.md`（每轮实验后回写）
- 文档里的版本、测试数量和性能数字都是带条件的历史记录；交付时以
  本次检查与运行结果为准，明确区分已实现/模拟验证/真机验证/待验证。

## 版本与基座纪律

- 推理基座一律对齐 runtime-team dev-1.0 `dev/images/USAGE_MATRIX.md`；
  昆仑芯推理腿 = `kunlun-infer-vllm/v1`（vllm-plugin-FL 需 ≥ `039fb46`）。
- 换镜像/插件版本时，先在本分支平台 README 登记，再开展实验。
