# 昆仑芯 P800 pooling/生成输出错误——完整排查记录（2026-11-10 ~ 11-17）

> 本文记录缺陷从发现到定案的完整实验过程，含被证伪的假说。
> 证据数据：`probes/results/xpu_pooling_defects_20261117.json`（结论性数据）
> 与 `probes/results/xpu_batch_composition_20261110.json`（首轮探针）。

## 0. 背景与最终结论速览

| | 缺陷一：prefix-caching 命中 | 缺陷二：跨 prefill 调度步 |
|---|---|---|
| 触发 | `enable_prefix_caching=True`（vllm 0.11 默认开）+ 长文本 KV 命中 | 单次调用总 token > `max_num_batched_tokens`(16384) |
| 性质 | 命中重算最后 token 时位置/偏移扭曲（cos≈0.55 半扭曲） | 后续步序列块表指向无效内存，从垃圾数据计算（与一切真实嵌入近正交） |
| 波及 | embedding + **生成**（贪心解码第 1 个 token 起分叉） | embedding（后续步全坏）+ **生成**（16/16 全坏，解码阶段使步 1 也坏） |
| 规避 | `enable_prefix_caching=False` | 单次调用总 token ≤16384（外层组批预算可钳制） |

安全包络（实测）：关缓存 + 单次 ≤16384 tok 时，64 条任意混长批逐位正确。
问题定位：昆仑芯算子层（kunlun_ops/vllm-kunlun 注意力后端）的**寻址/元数据
分支**错误——主路径算术逐位正确，错在缓存命中与跨步两个特殊分支。
映射契约（结果-请求对应）经 E1/E2 与交叉比对证明**始终正确**。

## 1. 发现（11-10，P800 验证日）

n64/n192 基准数值一致性 FAIL：B/C vs A 余弦低至负值（910C 同口径为 0.9997）。
首轮探针四项检查：重复调用确定 ✅ / 同长度批精确 ✅ / 语义合理 ✅ /
**长短混批短序列 cos=-0.004 ❌**——当时记为"长短混批缺陷"（后文将证明
这个初步定性是误导的：真正变量是缓存命中，且参照自身才是坏的那一方）。

## 2. 中断：宿主机驱动故障（11-15 ~ 11-16）

复查实验无法启动：vLLM 报 `wait for noc idle timeout`，60 秒跑不完一次
512×512 矩阵乘。判别矩阵逐步排除：新容器/旧容器、1/2/3/7 号卡、
vllm-kunlun 与 FlagOS 双栈、我的与他人容器、docker 与宿主机直跑、
计算与清理路径（写文件+`os._exit`）。结论：**内核驱动对新计算上下文
全局挂起，已运行进程不受影响**。管理员修复后恢复（11-17）。

## 3. 恢复后的系统排查（11-17）

### 3.1 排除映射错位（用户核心问题）

- **E1** 4×4 交叉余弦矩阵（2短+2长，单条参照）：对角线短文本 +1.0000，
  无任何非对角 ≈1.0 → **不是结果错位/置换**
- **E2** 顺序交换（[短,长] vs [长,短]）：损坏值跟随文本（300a 在任何槽位
  同为 +0.5461），不跟槽位

### 3.2 假说的提出与证伪

| 假说 | 实验 | 结局 |
|---|---|---|
| 长度差阈值（>255/256 坏） | E3 扫描 15~255 全对、E1 的 300 坏 | 初看成立 |
| **uint8 位置回绕**（300 mod 256=44 处取值） | E8：与 44-token 前缀嵌入比 cos=0.20 | **证伪**（应 ≈1） |
| 单调长度函数 | E5 边界扫描：250 坏、254~300 全好 | **证伪**（非单调） |
| E5 的混沌 ← 各假说无法解释 | —— | 转向"会话状态相关变量" |

### 3.3 破案：prefix caching 对照实验

同批文本、同批组成矩阵（2/3/4 条、任意顺序、缓存冷热）：

- `enable_prefix_caching=True`：短文本恒 +1.0000，300tok 恒坏（0.52~0.55，
  **同一错误值跨所有批组成复现**）
- `enable_prefix_caching=False`：**全部 +1.0000**

**最小复现**：同一 300tok 文本连发两次（bs=1，无任何混批），cos(v1,v2)=0.546。
**CPU transformers 真值判定**：cos(真值, 第一次冷缓存)=1.000（对）；
cos(真值, 第二次命中)=0.546（错）。

同时解释了 11-10 的"短序列损坏"：当时参照单条调用在混批**之后**执行，
命中的是混批留下的缓存——**坏的是参照，不是混批结果**。

### 3.4 第二缺陷：缓存关闭仍坏

基准脚本显式传 `enable_prefix_caching=False`，11-10 却 FAIL → 还有独立
缺陷。规模实验（缓存关）：64 条混长 35/64 坏。边界矩阵（缓存关）：

```
64×64tok   (总  4k ≈1步): 0/64 坏   ← 单步内条数无关
 8×2048tok (总 16k ≈1步): 0/8 坏   ← 打满单步仍全对
16×2048tok (总 32k ≈2步): 8/16 坏
32×2048tok (总 64k ≈4步): 24/32 坏 ← 步数越多坏越多
max_num_batched_tokens 调小到 4096（步更多）: 52/64 坏 ← 更糟
```

**触发条件 = 单次调用跨多个 prefill 调度步**，与混批、条数无关。

### 3.5 铁证（交叉比对实验）

16×2048 两步调用：**第 0~7 项（步1）全对，第 8~15 项（步2）8/8 全坏**。
把每个损坏向量与批内全部参照交叉比对：无任何非对角 ≈1.0（交叉 cos 仅
0.01~0.12）→ **排除"读到其他序列 KV"的串扰假设** → 损坏向量与一切真实
嵌入近正交 = **从无效/未初始化/已释放的 KV 块计算**（块表指向无效内存）。

补充发现：同形状调用在无批量调用历史的会话中可全部正确（0/16、0/32）
→ 触发受**块分配器空闲布局（会话历史）**影响——解释了此前所有混沌复现。

### 3.6 生成路径验证（影响面升级）

同一权重改 `task=generate`（检查点键名重映射为标准 Qwen3ForCausalLM
布局；embedding 结论均在原始检查点取得，重映射非缺陷来源）：

- **缺陷一×生成**：同一 400tok 提示贪心解码两次（缓存开），token 序列从
  第 1 个实质 token 完全分叉
- **缺陷二×生成**：缓存关，16×2048 批量调用 vs 逐条调用：16/16 输出
  不一致，全部从第 0~1 个 token 完全分叉（32tok 仅 0~1 个相同）→ 排除
  fp16 批数值噪声（那应是晚分叉+高重合）；**解码阶段的跨步 KV 读取使
  步 1 序列也全坏**（embedding 无解码阶段故步 1 完好）

→ 两缺陷**通杀 pooling 与生成**；vllm serve + 默认缓存或任何多步连续
调度下输出均不可信。

## 4. 定位与归口

- 层次：昆仑芯算子层（kunlun_ops / vllm-kunlun 注意力后端）
- 性质：**寻址/元数据错误而非算术错误**（主路径算术逐位正确；错在
  缓存命中与跨步两个分支的块表/位置处理）
- 黑盒边界：Python 适配层喂错元数据 vs 编译内核寻址分支错，需厂商源码切分
- 上报建议表述：排查 prefill/attention 路径在 ① prefix-caching 命中重算
  ② 跨调度步块表续用 两个分支的块表寻址与偏移处理
