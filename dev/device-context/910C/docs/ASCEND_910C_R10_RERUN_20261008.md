## 2 ⚠️ 偏离项 1：共享模型文件被存储层静默损坏（**与本层无关，但阻塞了两条腿**）

### 2.1 现象

首跑时两条腿**同时**失败，而它们的共同输入只有一个 —— 模型：

- 训练腿：`[step 0] loss=nan` … `[step 49] loss=nan` ⇒ `TRAIN_LEG_FAIL 5/6`（**能跑完 50 步**、4293.9 tok/s，只有 loss 数值判据失败）

### 2.2 逐步排除（四步，每步都排除掉一类嫌疑）

| 步 | 做法 | 结果 | 排除 |
|---|---|---|---|
| 1 | **逐卡对照**：同一命令分别在容器内 3 张可见设备（davinci0 / davinci2 / davinci3）各跑一次推理腿 | **三张卡全部 NaN** | ❌ 不是卡的问题 |
| 2 | **CPU 前向**：不经本层、不经 NPU，纯 CPU `AutoModel.from_pretrained(...)` 前向 | `nan = True, mean = nan` | ❌ 不是设备上下文层的问题 |
| 3 | **权重扫描**（`safetensors` 读取 310 个张量 / 595776512 元素） | **2 个张量含非有限值：`embed_tokens.weight` 27615 个 NaN + 18 个 Inf；`layers.1.self_attn.v_proj.weight` 6781 个 NaN** | —— 锁定到文件 |
| 4 | **裸字节核验**（绕开所有框架：手解 safetensors 头 → 按偏移直接读文件字节） | 首个 NaN 位置字节 = `ff ff`（bf16 负 NaN 位型），文件绝对偏移 372453404 / 57552940 | ❌ 不是"读错了" |

**旁证（同机其它模型全干净）**：

```

```

### 2.3 损坏的量化与"为什么不是旧病"

- 受影响字节集中在 **8 个 1 MB 块**（索引 54/55/56/72/73/259/260/355）内的 **410 个 4 KB 页**；
  其中既有"值变成 NaN"的页，也有**「值仍然有限、但已被改写」**的页（第二轮比对才发现，见 §2.5）。
- **同一路径在 09-30（r9 轮）还是好的**：训练腿 loss `15.4498 → 11.1479`、推理腿区分度 `0.6391`
  —— 有 NaN 权重时 loss 不可能下降 ⇒ 文件当时完好。
- 而本日 `stat` 显示 **mtime 与 ctime 均为 `2026-09-08 17:18:10`**（未变）⇒ **不是正常写入路径改的**。
- 存储层线索：该目录所在设备 **`/dev/md127` 是 RAID5 且处于降级状态** ——

```
md127 : active raid5 nvme0n1[0] nvme2n1[2] nvme1n1[1]
      11251817472 blocks super 1.2 level 5, 512k chunk, algorithm 2 [4/3] [UUU_]
```

`[4/3] [UUU_]` = **配置 4 块盘、当前只有 3 块在线**（缺 1 块，降级运行）。
⇒ 结论指向**存储层静默损坏**（机制层为推测，事实层为实测：字节确实是坏的、阵列确实降级）。

## 3 偏离项 2：编排脚本缺 `DC_ROOT`（**我的脚本缺陷，不是代码回归**）

首跑训练腿 12 秒即失败：

```
File ".../prototype/runtime/proto/proto_train_leg.py", line 110, in <module>
    import runtime
ModuleNotFoundError: No module named 'runtime'
```

根因：`proto_train_leg.py` 的根解析是

```python
ROOT = os.environ.get("DC_ROOT", "/mnt/raid/hliu553/runtime-team/dev/device-context")
```

—— **默认值写的是宿主旧克隆的 `dev/device-context` 目录**（不是本次原型根 `.../prototype`），
所以只有显式给 `DC_ROOT` 才能 import 成功。这正是手册里记的前置条件
（「训练腿需 `DC_ROOT=<原型根>` 且在 `runtime/proto/` 下起」）；**本轮我的编排脚本漏了这一条**，
r9 那轮之所以通过，是因为当时的调用给了 `DC_ROOT`。补齐 `DC_ROOT` 后训练腿的失败点就只剩模型（§2）。

> ⚠️ 顺带记一条**潜在坑**：该默认值指向**一个真实存在但版本陈旧的目录**
> （`/mnt/raid/hliu553/runtime-team` 现停在 `57cb9dd`，落后当前 tip 若干提交）。
> 目前表现为"响亮地失败"（`ModuleNotFoundError`）而不是"静默跑旧代码"，尚可接受；
> 但**一旦该目录下出现同名 `runtime/` 包，就会变成"静默跑旧代码"** —— 属于"看起来通过"家族，建议后续把默认值改成基于 `__file__` 解析。
