## 更正：MLU590 的 C13 不是「平台不具备计时能力」

归档（`probes/t1_duty_cambricon_20261014.json`）里 C13 = SKIP，原因是
`RuntimeError: CNRT error: failed to call the driver-…` —— **长得像寒武纪驱动缺陷**。
本轮补上「建可计时事件」入口后，MLU590 **计时正常**：`11.381 ms`（另有 10.363 / 10.416 / 11.453 ms 三次复现）。
⇒ 与 910C / PPU 同因：**统一 API 缺入口**，不是平台限制。审计随之 `62/0/16 → 63/0/15`。

⚠️ 四家里**只有 P800 是真平台缺口**（补入口后仍恒 `0.0`，裸 torch 正反向复核）。

## 本轮暴露的共享层缺口（已登记，未夹带修改）

⭐ **两腿对 `DC_MODEL` 传法不一致**：`proto_infer_leg` 有 `resolve_model`（把 HF 缓存根解析到
`snapshots/<hash>`），`proto_train_leg` **没有** ⇒ 同一份 `DC_MODEL=/hf_cache/hub/models--Qwen--…`
推理腿过、训练腿报 `ValueError: Unrecognized model in …`。
本轮按历史用法（先解析 snapshot 路径）绕过，**没有在 parity 跑里顺手改共享层**（改共享层须四实例复验）。
⇒ 待办：训练腿补同一解析 + 四实例复验。

## 环境与两条踩坑

- `tza-0a06-ai01-em9` · 容器 `dc-mlu590-hliu553`（自 09-22 Up，复用未重启）·
  py3.10 / torch 2.7.1+cpu / torch_mlu 1.29.2 · 8× MLU590-M9（`cnmon` 0% 无进程）。
- ⚠️ **`DC_DIST_BT` 必须显式 `cncl`**：本原型对寒武纪拒绝兜底 `gloo`（会静默退化成纯 CPU 集合通信）。
  缺该变量时两 rank `exitcode 2`，日志给出探测指引。
- ⚠️ **`/hf_cache` 是容器内路径**（宿主 `/srv/data/hf_cache`）：在宿主算 `ls -d $MODEL/snapshots/*/`
  得空 ⇒ 回落缓存根 ⇒ 训练腿仍报 `Unrecognized model`。须在**容器内**解析。
