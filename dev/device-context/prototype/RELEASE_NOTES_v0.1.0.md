## 1. 这是什么

设备上下文方向交付的**统一运行时原型**：把"设备、内存、流与事件、错误码翻译、状态恢复"
做成与芯片无关的统一 API，下层由各厂商 backend 插件实现。

**一句话主张**：新增一家芯片 = 实现一个 backend + 跑通 conformance。
（本轮 flagos 后端从零到 conformance 13/13 即是一次实证。）

适用：作为运行时层**设备抽象底座**被上层（算子/编译/转换器）与下层（分布式训练推理）共同使用。

## 3. 接入方式

```python
import sys; sys.path.insert(0, "<path-to>/prototype")
import runtime

runtime.use("ascend")          # 或 "flagos"；切换芯片只改这一行
runtime.set_device(0)
s = runtime.create_stream()    # 统一 Stream 对象
```

- `prototype/` 目录**自包含**：conformance 依赖的 errors / recovery / device_state / npu_events
  已内置，整体拷出即可用（实测换路径后 conformance 13/13）。
- 详细 API 与两条硬纪律见 `prototype/README.md`。

## 4. 两条硬纪律（用错会出真问题）

1. **跨流传递内存必须 `record_stream`**
   `tensor.record_stream(using_stream)` 告知缓存分配器该缓冲仍在被使用，
   否则内存可能被提前回收给其他任务 → 数据竞争。统一 `Stream` 已提供该方法。
2. **错误隔离是分层的**
   单个接口调用失败只影响该次调用（其他流不受影响，已实测）；
   芯片级故障影响该设备全部流，**必须走设备级 `recover_device`，流级重试无效**。
   按 `FlagosError.disposition` 处置：`retry` / `raise` / `replay` / `device_recovery`。

**补充纪律（本轮实测）**：调用 `translate_error` 必须传**完整原始消息**，不得截断——
截断会丢失语义导致保守误判（参数错误被判成可重放）。

## 5. 验证结果（910C 实跑）

| 项 | 结果 |
|---|---|
| 组件自检 | 昇腾真机 **37/37**（无 NPU 环境时昇腾项自动 SKIP） |
| conformance（ascend） | **13/13** + 推理 **6/6** |
| conformance（flagos） | **13/13**（锁定训练镜像） |
| 训练腿 2 卡微调 | 两 rank 均 **6/6**：loss 15.4497→11.15、2117 tok/s、通信三类对照全对 |
| 推理腿服务化 | **10/10**：维度 1024、区分度 0.4123、108 句/s（p50 27.4ms）、超长输入 → L2_PARAM/raise |
| 错误注入 → 恢复闭环 | 推理腿 **5 闭环**、训练腿 **4 闭环 / 1 跳过**，业务均继续 |

## 6. 已知限制（如实列出）

| # | 限制 |
|---|---|
| 1 | flagos 后端**无有界同步**（原生同步为阻塞式），超时类能力不可用 |
| 2 | `real` 模式设备重建可用但**未作生产默认**，需多卡多进程压力测试调优后再启用 |
| 3 | 流优先级：ascend 支持范围查询与并发正确性，**调度效果**需压测验证 |
| 4 | 接口仍为 **v0.1** —— 原型期允许破坏性变更，v1.0 前会提前知会 |
| 5 | `ERR99999` 偶发进程终止：复现 1 次、后续 4 次未复现，**观察项，不作结论** |
| 6 | 历史模型（Qwen2.5-1.5B / Qwen3-4B）尚未在统一原型上复跑 |
