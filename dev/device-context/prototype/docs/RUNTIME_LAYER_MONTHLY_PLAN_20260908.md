## 附录：长期协同机制（精简版，长期有效）

**问题路由**（谁定位、谁修）：

- **精度差距 / 性能不达标**：精度方向用 Oracle-Device 回归 / Profiling 五段分解（算子/同步/显存/调度/通信）定位 → 算子差异归**算子**（涉及实现升级上层算子层联调）、设备因素归**设备**、显存归**显存**、调度归**调度**、通信归**分布式**；修复后由精度复测闭环。
- **故障**：监控检测 + 设备错误分级（L1 重试 / L2 上抛 / L3 重放+重调度 / L4 设备恢复+检查点）。
- **规模化通信异常**：分布式在 8 卡/多机检测 → 底座问题回流设备、并行策略分布式自优、厂商栈缺陷分布式跟进。

**规模递进**：设备只负责最小正确规模（≤2 卡）；8 卡→多机多卡归分布式；高并发归调度；规模化观测归监控/精度。避免各方向挤在 2 卡上重复验证。

**升级路径**：子方向内 → 跨方向三方会诊 → 总组裁决 → 运行时层外（算子问题经算子方向、并行问题经分布式方向，与上层算子层/编译层联调）。

**固定联调对**（每月至少一次同步）：设备↔分布式（规模化）、算子↔精度（精度定位）、调度↔分布式（调度执行）、显存↔调度（显存调度）、监控↔精度（指标口径）、设备↔监控（恢复原语）。
