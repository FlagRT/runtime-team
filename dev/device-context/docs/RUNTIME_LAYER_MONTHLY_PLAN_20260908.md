## 1. 运行时层子方向与职责域

| 子方向 | 职责域（对应模块拆分表） | 负责人 |

| **performance** | 指标采集与性能评测：Benchmark 平台、吞吐/时延口径、统一验收报告汇总 | 待定 |
| **监控可靠性**（专人） | 监控、恢复与热加载：算子与全链路指标采集、故障检测与多级恢复、模型热加载与多卡迁移、监控体系搭建 | 待定 |
| **精度性能**（专人） | 精度和性能诊断：Oracle-Device 中间结果回归、性能 Profiling 助手、精度差距定位 | 待定 |
| 总组（协调层） | 镜像锁定（stack.lock）维护、接口约定文档、合入把关、跨方向联调、月底合稿 | 待定 |

**分工原则（组内迭代循环）**：

```
device-context 交付底座组件（统一 API + 某芯片 backend，版本化下发）
        ↓
其余子方向基于底座做各自开发（不直接触碰厂商 Runtime 差异）
        ↓
使用中发现问题 → 反馈 device-context → 修复迭代 → 新版本组件
        ↓
每月 25 日各子方向交产物 → 总组合一稿 = 运行时层本月对外指标与产物
```

**合入把关**（沿用战略文档 §5 五项标准）：镜像与 stack.lock 一致 ② 命名合规 ③ 接口约定章节写完且有下游确认 ④ 能跑通自己那段 demo ⑤ 无新环境分叉。

## 4. 月底合稿机制（制度化）

```
每月 20 日   各子方向自检：本月产物是否覆盖 §2 对应指标
每月 22 日   交叉评审：相邻子方向互查（dc ↔ memory ↔ performance ↔ 监控 ↔ 精度）
每月 25 日   各子方向向总组提交：产物清单 + 证据链接 + 遗留问题
每月 26-28 日 总组合稿：运行时层月度报告（对外指标逐条对应产物）
每月底       提交 + 下月计划发布（含组件版本发布说明）
```

**合稿固定章节模板**（运行时层月度报告）：
1. 本月考核指标逐条对照（产物/证据）
2. 各子方向交付明细（六方向分节）
3. 组内迭代记录（dc 组件下发版本 × 下层反馈 × 修复闭环）
4. 遗留与下月输入
