## 1. 运行时层七个子方向与职责域

| # | 子方向 | 职责域（按模块拆分表功能说明） | 负责人 |
|---|---|---|---|
| 1 | **设备抽象与执行上下文** ⭐我们 | 抽象不同芯片 Runtime 接口，统一设备、内存和执行句柄及生命周期管理；统一 Stream 语义、Host/Device 异步传输、页锁定内存与双缓冲流水线、同步语义、错误码翻译和设备状态恢复；**Backend 插件机制与注册表**（框架起头） | Kistich |

| 3 | 任务调度与执行引擎 | 在线与离线任务调度：动态 Batch 与请求合并（长度分桶+多级预装箱降 Padding）、优先级与超时控制（队列/取消/降级/Fallback/SLA）、离线批量处理引擎；多阶段流水调度：检索-排序-生成流水编排 | 待定 |
| 4 | 显存与缓存管理 | 显存池与分层缓存：分配复用与碎片整理、张量分配与碎片整理、降低峰值显存和频繁分配开销；Embedding/KV Cache 卸载：Host/Device 分层存储与相关内存释放 | 待定 |
| 5 | 分布式训练与推理支撑 | 多卡执行与通信：承接编译层并行计划，统一多卡执行、跨卡同步和批处理策略；通信与检查点管理：支持通信异常检测、任务重启及基于检查点的恢复 | 待定 |
| 6 | 监控诊断与可靠性 | 监控、恢复与热加载：算子与全链路指标采集（Prometheus 系指标）、故障检测与多级恢复（OOM/通信中断检测→重试/迁移/恢复）、模型热加载与多卡迁移（热更新/灰度切换/长任务稳定性） | 待定 |
| 7 | 精度与性能分析 | 精度和性能诊断：Oracle-Device 部分中间结果误判回归（层层比对英伟达与国产结果，定位浮点异常/舍入误差来源）；性能 Profiling 助手（汇总算子与全链路指标、关键图节点、Backend 和运行时状态定位瓶颈）；Benchmark 与性能评测 | 待定 |
| — | 总组（协调层） | 镜像锁定维护、接口约定文档、合入把关、跨方向联调、**月底合稿** | 待定 |

**与子方向 1 的两个衔接约定**（设备上下文是底座，其余子方向都踩在上面）：
- 子方向 6 的"多级恢复"调用子方向 1 的 `recover_device`（probe/real/hybrid）能力原语——**检测与编排归 6，恢复执行归 1**；
- 子方向 3 的任务执行、子方向 5 的多卡执行，全部通过子方向 1 的统一设备抽象获取设备/流/事件——**换卡不改代码由 1 保证**。

**分工原则（组内迭代循环）**：

```
device-context 交付底座组件（统一 API + 某芯片 backend，版本化下发）
        ↓
其余六个子方向基于底座做各自开发（不直接触碰厂商 Runtime 差异）
        ↓
使用中发现问题 → 反馈 device-context → 修复迭代 → 新版本组件
        ↓
每月 25 日各子方向交产物 → 总组合一稿 = 运行时层本月对外指标与产物
```

## 4. 月底合稿机制（制度化）

```
每月 20 日   各子方向自检：本月产物是否覆盖 §2 对应指标
每月 22 日   交叉评审：七子方向轮转互查（1↔4、2↔7、3↔5、6↔全体）
每月 25 日   各子方向向总组提交：产物清单 + 证据链接 + 遗留问题
每月 26-28 日 总组合稿：运行时层月度报告（对外指标逐条对应产物）
每月底       提交 + 下月计划发布（含组件版本发布说明，子方向 1 出组件 release note）
```

**合稿固定章节模板**（运行时层月度报告，七方向分节）：
1. 本月考核指标逐条对照（产物/证据）
2. 七子方向交付明细（每方向一节：工作内容/产物/证据）
3. 组内迭代记录（子方向 1 组件下发版本 × 下层反馈 × 修复闭环）
4. 跨子方向联调记录（如 11 月新芯片：1 的 backend × 2/3/4/5/6/7 的适配）
