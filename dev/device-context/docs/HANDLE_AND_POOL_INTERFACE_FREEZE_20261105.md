# 接口冻结 v1 · 统一内存句柄与显存池界面

> **这是什么**：招标功能拆分表「统一内存句柄与显存池界面」交付条目的**联合冻结文件**——句柄定义、用途标签枚举、所有权 / 所属流 / 强持有生命周期 / 能力缺失返回语义。依据 ADR-0013 §3.4（登记处 = 指挥台仓 `flag_RT/decisions/` 同号文件；一句话 = 该接口由显存方向与设备方向联合冻结同一份文件，只冻接口、不合写实现）。
> **冻结状态**：v1 已冻结（2026-11-05）——池侧草案经用户与 device-context 负责人（刘鸿彬）同步，**双方无异议**。变更规则：只追加新版本（v2），既有语义不改写；用途标签枚举「可增不可改语义」。
> **归属**：本文件落 device-context 目录（接口面在统一后端接口侧更自然，池侧建议、对方认可）；显存方向的设计文档（FlagMemory `docs/design/`）与接口文档已改指本文件为准。
> **不是什么**：不是池的设计文档（在 FlagMemory `docs/design/`）；不要求 device-context 实现任何池行为——**标签只透传，语义由池解释**。

## 一、不变部分（沿用统一后端接口既有定义，一字不改）

| 项 | 内容 |
|---|---|
| 既有五公共字段 | 句柄号、种类、后端名、设备序号、字节数——含义不变 |
| 纪律一 | **厂商指针不进句柄**（否则「换芯片不改代码」被悄悄破坏） |
| 纪律二 | **成对释放；重复释放与非本层句柄必须报错**（统一层已用句柄登记表统一拦截，沿用、不重造第二套） |
| 纪律三 | **能力如实声明：未声明的能力被调用时报错，不得静默退化** |

## 二、新增字段一：用途标签

- **谁填**：申请方（谁申请谁打标）；**谁解释**：显存池；**device-context 只透传、不实现任何标签行为**。
- 枚举六类，**可增不可改语义**：

| 标签 | 含义 | 池的处理（解释侧，写明供核对） |
|---|---|---|
| 权重 | 模型参数，服务生命周期常驻 | 永不回收、不进复用池，只记账 |
| KV 缓存 | 推理上下文缓存 | 可复用、可分页、可降级主机侧（分层存储主对象） |
| 激活 | 前向/反向中间结果 | 短生命周期，优先复用（块复用主战场） |
| 通信缓冲 | 集合通信收发缓冲 | **不得被池回收**，只记账 |
| 临时工作区 | 算子工作空间 | 最优先回收 |
| 未声明 | 申请方没给 | 最保守：不回收、不复用 |

- **为什么必须在句柄上**：通信缓冲等由其他方向申请，池只有从句柄看到标签才知道「这块别动」——这是「通信缓冲与显存生命周期协同」条目的接口前提。

## 三、新增字段二：所属流（可选）

- 存**流标识**，不是流对象（避免生命周期纠缠）；缺省 = 默认流。
- 用途：流有序分配与回收屏障需要知道块当初在哪条流上分配（显存池「分级块池 + 流有序分配」交付的接口前提）。

## 四、写进使用约束的三条硬规则

> 注：`I-1` / `I-3` / `I-9` 为显存池组件内部不变量编号（命名空间 = 组件内部；唯一登记处 = FlagMemory `docs/design/显存池概念与设计基础.md` 第三节第 5 小节，不与总组编号体系撞号）。

1. **同一句柄在不同后端下的底座不同（昇腾 910C 接厂商裸分配原语 / 昆仑芯 P800 与平头哥 PPU 接框架缓存分配器 / 寒武纪 MLU590 未声明），任何消费方不得假设拿到的是裸内存**（`I-9`）。
2. **持有流必须强持有，禁止弱引用自动清理**——依据 device-direction 2026-11-03 四家矩阵：流 + 弱引用 + 被回收 = 进程退出期段错误，平头哥 PPU 与昇腾 910C 两家中招（`I-3`）。此条写在接口文件的使用约束里，不只在池代码内。
3. **所有权与生命周期语义**：成对申请 / 释放；重复、过期、跨池凭据由账本拦截，不依赖厂商报错（两家对二次释放行为相反——昇腾静默成功、昆仑芯如实报错，`I-1`）；池对登记的流强持有至池安全销毁。
