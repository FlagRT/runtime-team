## 二、设备方向对四个待补问题的答复（摘要）

1. **int8 宽度/字节序**：Python 面两字段就是 `int`（int8/int64 只约束值域：usage_label∈[0,127]、owning_stream∈{-1}∪[0,+∞)）；不定义字节序与二进制 layout。C 头出现时（触发式，对齐 ADR-0015）再定结构体落位，届时以「可增」方式补 serial 小节。
2. **句柄结构体落点**：**不并入** `MEMORY_HANDLE_KEYS`（base.py L36，五公共字段「一字不改」是冻结条款）。新增独立常量 `HANDLE_EXT_KEYS = ("usage_label", "owning_stream")`；`allocate()` 扩签名 `allocate(size_bytes, ordinal=0, *, usage_label=0, owning_stream=0)`——纯透传、不解释、只做 int/非负这一层的值域校验。既有判据不受破坏（`backend_offline_check` 的句柄判定是**子集**判断 `set(MEMORY_HANDLE_KEYS) <= set(h)`；`duty_response_audit` 的 `PROMISED_UNIFIED_CONSTS` 若纳入新常量须同批更新）。**排期：与寒武纪能力声明更新同窗口**（一次真机窗口完成两件）。
3. **流标识分配策略**：v1 阶段由申请方（池）分配（`register_stream` 已返回 int）；设备方向不建第二张流表。若未来确需统一层发 ID，走冻结文件变更条款升接口，不在本登记内扩。
4. **私有扩展区规则**：登记须带后端名前缀（`ascend.xxx` / `kunlun.xxx`），追加进本文件 values；统一层照旧透传；池遇未识别标签（含私有区）一律报错。
5. **登记文件归属**：随冻结文件同目录（`dev/device-context/docs/`）作为机读配套；Accepted 后与冻结文件同版本演进（冻结文件出 v1.1 时引用本登记）。
