## 2. 四个「实测才敢说」的结论

1. ⭐ **`NCCL_SOCKET_IFNAME` 被基座镜像写死为 `eth0`，而本机没有 `eth0`（真网卡 `bond0`）** ⇒
   不覆盖时 `init_process_group('nccl')` **能建组**、**第一次真实集合通信就失败**
   （`Bootstrap : no socket interface found`）。**同机他人容器也是 `eth0`**。
   ⇒ 我们启动容器时显式 `-e NCCL_SOCKET_IFNAME=bond0`（写进 `hliu553-dc-dev.run.sh`）。
2. **集合通信后端名 = `nccl`**（不是 `pccl`）。`pccl`/`hccl`/`ucc` 均 `Unknown backend type`，
   `xccl` 未编译进本 torch；而底层库确实叫 **PCCL** ⇒ **引用必须区分「库名」与「后端名」**。
3. **上下文生命周期：本栈允许本层自建多个上下文并切换，且不影响 torch**（与 P800 相反）
   ⇒ 如实**声明** `context_lifecycle`（建 A/B → 切换 → 只销毁自己的 → torch 全程可用）。
4. **流优先级 4 档且可设可回读**（区间 `(0,-3)`）⇒ 是继第 3 家之后**第二个「多档」实例**；
   判据是 **C API 独立回读 == 请求**（不看构造参数回显）。
