## 2. 六个「实测才敢说」的结论

1. ⭐ **`NCCL_SOCKET_IFNAME` 被基座镜像写死为 `eth0`，而本机没有 `eth0`（真网卡 `bond0`）** ⇒
   不覆盖时 `init_process_group('nccl')` **能建组**、**第一次真实集合通信就失败**
   （`Bootstrap : no socket interface found`）。**同机他人容器也是 `eth0`**。
   ⇒ 我们启动容器时显式 `-e NCCL_SOCKET_IFNAME=bond0`（写进 `hliu553-dc-dev.run.sh`）。
2. ⭐ **`--network host` 下容器主机名 `ai-server` 不解析** ⇒ `torchrun --standalone` 的 rendezvous
   端点连不上，**静默挂 5 分钟**（300 s 超时）后才失败、且**无任何子进程输出**（很像"脚本卡住"）。
   ⇒ 启动脚本加 `--add-host=ai-server:127.0.0.1`（`getent hosts ai-server` 由空变为回环）。
   同一容器里 `mp.spawn` + `init_method=tcp://127.0.0.1:<port>` **不受影响**。
3. **集合通信后端名 = `nccl`**（不是 `pccl`）。`pccl`/`hccl`/`ucc` 均 `Unknown backend type`，
   `xccl` 未编译进本 torch；而底层库确实叫 **PCCL** ⇒ **引用必须区分「库名」与「后端名」**。
4. **上下文生命周期：本栈允许本层自建多个上下文并切换，且不影响 torch**（与 P800 相反）
   ⇒ 如实**声明** `context_lifecycle`（建 A/B → 切换 → 只销毁自己的 → torch 全程可用）。
5. **流优先级 4 档且可设可回读**（区间 `(0,-3)`）⇒ 是继第 3 家之后**第二个「多档」实例**；
   判据是 **C API 独立回读 == 请求**（不看构造参数回显）。
6. ⚠️ **两条腿在判据通过后、解释器退出阶段段错误** —— 已定位到与 `runtime.create_stream()` 强相关，
   但**精确触发条件尚未收敛**、**归属未定**（见 §4 与专项报告 §4）。
