## 2. 六条关键认知（调研得出，接入前必读）

1. **组件层三件齐备、运行时层为零。** 编译器有完整设备后端目录；算子库有专门厂商后端目录；推理插件已列为支持。
   而**运行时项目 20 仓 + 基座项目 22 仓中，该厂商条目为 0** ⇒ 前三实例的「双镜像路径」在这里**断了**。
2. **算子库靠「环境变量」识别该厂商**（不是判设备名）⇒ 上机时必须确认该变量**由镜像或 SDK 设置**；
   否则算子库认不出设备，而**报错文案大概率指向别处**（本方向已多次被这类"指错方向"的报错坑过）。
3. **应用层只有 sglang 镜像、没有 vLLM 镜像** ⇒ 服务化这条腿要么换 sglang，要么自建 vLLM 应用镜像；
   与本项目**统一服务入口**不一致，**须先定口径再动手**。
4. ⚠️ **缩写同名不同家。** 该厂商的集合通信库与**另一家**的库**缩写完全相同**，而统一通信库的后端表里
   那个缩写**指向的是另一家** ⇒ **引用必须写全称，不要按缩写认库**。
5. **官方构建配置里该厂商是最不成熟的一档**：段内仅 **8 行**，缺 `driver` / 编译器 / SDK / 应用依赖 / 环境变量
   **五个字段**；注释原文写明「**尚无基座镜像**」，且其 CI 的真实基座镜像托管在**厂商云**上（非公共 Harbor）。
6. ⚠️ **档位三套并存**（官方配置 / 编译器手册 / 算力平台三方版本互不一致）⇒
   **选档第一判据仍是宿主驱动**，而这条官方恰恰没给（见 §1 末行）。
