## 4 服务化吞吐与显存参数：四臂单变量对照

详见 `probes/gmu_ab_20261103_out/MANIFEST.md`。要点：

| 臂 | gmu | seqs | 吞吐 句/s | 显存（外部采样） |
|---|---|---|---|---|
| A2（10-26 口径） | 0.9 | 256 | 115.51 | 90.0%（88,517 MB） |
| A1 | 0.9 | 128 | 102.13 | — |
| B（11-03 前的默认） | 0.4 | 128 | 105.79 | 40.0%（39,341 MB） |
| C | 0.4 | 256 | 111.21 | — |

四臂**区分度全为 0.4118、全部 10/10**。派生处置：

1. **gmu 默认 0.4 保留**（与 memory 建议一致）：显存 90%→40%，吞吐代价约 4%。
2. **取消 `max_num_seqs=128` 默认**：它不省显存（显存由 gmu 决定），却掉吞吐 5.1%（0.4 档）/13.1%（0.9 档）；
   gmu 0.4 下 vLLM 自报最大并发 `84.45x`，128 确实在卡并发。⇒ embed 形态改为**不传**（VLLM 默认 256），
   需要限流时显式 `MAX_NUM_SEQS=<n>`。**这是对 memory 建议 #1 的部分不采纳，依据即上表。**

v2 验收当轮 91.65 句/s 的归因：同配置（0.4+128）换到 ppu1 复测 **105.79**，与归档 105.74 差 0.05%
⇒ 当轮读数受 **ppu0 被他人占用 5,533 MiB** 与 **共享盘满** 影响，非镜像/默认值缺陷。

## 6 本轮核出的脚本缺陷（已修）

**`run_t3` 判据读错目录 ⇒ 假 FAIL**：`run_t3_ppu_serve_20261014.sh` 只把宿主视角 `HO` 拼了 `$RUNID`、
容器视角 `O` 没拼 ⇒ `DC_OUT_DIR="$O/form"` 写到扁平旧目录，而 verdict 的 `grep` 读 `$HO/<runid>/form/`。

- 现象：服务臂**实际 `SERVE_STANDARD_PASS (ready=1 smoke=1)`、就绪 45 s**，汇总却印 `[A] 未通过`；
- 反证：`probes/v2_acceptance_20261103_out/s09_t3_form_flat/serve_standard.log`；
- 影响面：`run_t3` / `run_t456` / `run_t5` **三处同族**，且 10-26 那一轮同一位置同样是空的
  ⇒ **该假 FAIL 自 10-14 起一直存在**，此前每轮的 form 证据都被下一轮覆盖；
- 修法：三处均加 `O=$O/$RUNID`，并在开头各打印宿主/容器两个目录做自证；已 `bash -n` 通过。
- 已写进接入手册 §9 **坑 22**（同批新增坑 23「共享存储写满会伪装成产品缺陷」）。
