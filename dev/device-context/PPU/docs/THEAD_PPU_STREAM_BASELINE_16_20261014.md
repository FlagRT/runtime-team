## 3. S-12 的「调度效果」：PPU 与 MLU590 结论不同（**必须分开读**）

「优先级区间可用」与「优先级带来实质调度效果」是**两件事**，四家的 `D2` 对照结论如下：

| 实例 | 区间 | 调度效果结论 |
|---|---|---|
| 910C | 不声明 `stream_priority_control` | `NOT_APPLICABLE`（无从构造对照） |
| P800 | 单点 `(0, 0)` | `NOT_APPLICABLE`（区间退化） |
| MLU590 | `(0, -3)` | `PASS` · `effect_observed=True`（**有排队争用**场景测到 5.3–8.1 ms 净效应） |
| **PPU（本轮）** | `(0, -3)` | `PASS` · **`effect_observed=False`**（**如实记录：未观测到实质效果**） |

PPU 本轮（`t6_sched_effect_ppu_fixed.log`，`STREAM_PRIORITY_SCHED_EFFECT_PASS`）的逐项读数：

- `E1` 区间 `raw=(0, -3)` ⇒ `hi=-3 / lo=0`，`supports[control]=True`、`supports[readback]=True`；`E2` 请求与回读**逐值一致**；
- `E3` 工作量级：每流 60 次链式 2048² matmul = **34.873 ms**（单次 ≈ 0.5812 ms）；gate 慢活实测 **71.389 ms**；
- `D1` 分辨力：一趟扫描 1.13 µs = 工作量级的 **0.003%**（阈值 ≤ 5%）⇒ **仪器分辨力足够**；
- `G2` **正对照通过**（同优先级、工作量差 2× ⇒ 先完成 8/8，中位差 34.07 ms）⇒ **测量确实能判出差异**；
- `G3` 噪声基线：同优先级等量工作 ⇒ 3/8、中位差 −0.461 ms；
- **`G1`（gated，两流同时就绪）**：`hi(-3)` 先完成 **6/8**（阈值 6 ⇒ 胜率**刚好达线**），但**中位差仅 0.4821 ms** ≪ 阈值 `8.7182 ms`（25% 工作量级）⇒ **未观测到实质性效果**；
  （**同日重跑一次**：胜率 8/8、中位差 `0.5061 ms` / 阈值 `8.9364 ms` ⇒ **结论一致**：幅度比阈值低一个数量级，胜率的波动属阈值附近的噪声）
- `G4`/`G8`/`G7`（ungated，一条已运行、另一条才提交）构成 2×2：G4（取值 0 先提交）⇒ 先提交者胜（0/8，−1.0355 ms）；G8（取值 −3 先提交）⇒ **仍是先提交者胜**（8/8，+1.0223 ms）；G7（同取值对照）⇒ 先提交者胜（−1.0161 ms）⇒ **三种情形一致指向「提交顺序主导」**，`G10` 汇总**如实标 False**。
- `G6`/`G9`：取值 1 不在区间 `[-3, 0]` 内 ⇒ **如实跳过**（不臆造读数）。

⚠️ **判读纪律**：「胜率 6/8」与「幅度 0.48 ms」两个条件**必须同时满足**才算有效果；只报胜率会把噪声当效果。

## 4. 证据形态差异的如实说明（不要误读为"不一致"）

| 项 | 差异 | 事实与理由 |
|---|---|---|
| S-6 | 集合通信范围 | PPU 侧为**单机 2 卡 DDP 梯度 `all_reduce`（后端 `nccl`）**，未做 TP 场景 ⇒ 排他性弱于 910C；"梯度同步正确 + loss 正常下降"足以证明"通信与流绑定"成立 |
| S-7 | 计数 5/5 vs 4/4 | 判据集不同：910C/P800/MLU590 计入 5 项；本方向探针在 PPU 上按**契约内 4 项**判定，另 1 项（capture 内切流）为**契约外用法观察项**，实测**不容忍**（`AcceleratorError`）——与 P800 同形 |
| S-9 | 注入形态 | PPU **无 ACL 107015 等价数字码**（异常消息内无厂商码）⇒ 用参数类异常替代；验证的语义同为"单次调用失败是否影响其他流"。⚠️ 设备级隔离为语义推断（探针内已标注） |
| S-14 | 触发形态 | 507046 是昇腾专有码；PPU 侧验证的是"**有界返回**"语义本身（注入后 `L3_EXECUTION/replay`、进程存活、业务继续） |
| S-12 | 调度效果 | ⚠️ **同一区间形态、不同效果结论** —— 属**如实记录的实例差异**，不得为对齐而改写（PPU 为 `effect_observed=False`） |

## 5. 本轮附带发现（跨后端缺陷，已修）

S-12 探针在本轮**首次跑出「全线 FAIL」**：`RuntimeError: 该流已被 release_stream() 释放` ——
根因是**平台侧 `weakref` 悬垂**（PPU 的 torch 流对象回收后 weakref 未置死，地址复用时解析出新对象）
⇒ 本层 `_released_streams`（按 `id` 键 + 身份复核）把**刚建的流**误判为"已释放"。
已按**机制无关**方式修复（新建登记即清除同 id 旧记录 + 类型复核），并给出**修前/修后交替对照**与非空转判据。
全文：`PPU_T3_T6_AND_WEAKREF_20261014.md` §4；证据：`../probes/repro_release_recreate_20261014/`。
