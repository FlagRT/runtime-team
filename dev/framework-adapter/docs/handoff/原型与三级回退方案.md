# 算子接入原型与三级安全回退方案

负责人：顾宬

版本：v0.2，2026-10-09；供跨方向接口评审

## 目标与当前结论

本方向负责把统一算子库接入框架调用路径，并在执行前选择合法实现。现有910C原型验证了SiLU接入、部分输入条件判断及作用域恢复；RMSNorm入口已接通但未获得模型替换准入。通用注册、多候选选择、vLLM/训练及芯片级任务恢复仍需开发与联调。

设备后端、流和设备恢复复用device-context，不重复建设；算子内核由算子组维护。原生实现也有支持条件，并非任何错误都能通过回原生解决。

## 工程分层和调用关系

```text
任务启动 / 服务worker初始化
  ├─ 公共环境校验：镜像、挂载、源码版本、模型身份
  ├─ device-context：选择厂商后端、初始化设备、查询能力
  └─ framework-adapter：确定可用算子与策略，安装已知入口适配
                            │
模型 / 框架发起算子调用      ▼
                    语义映射 + 执行前支持判断
                       ├─ 已准入且满足条件 → FlagGems目标实现
                       └─ 未覆盖/禁用/不支持 → 合法的同设备原生实现
                            │
                  结果与路由记录 / 错误上报
                            │
           上层任务管理与设备方向协调恢复，不在算子内盲目重算
```

算子替换在worker进程内进行，不通过RPC传张量。底层实际运算仍走厂商PyTorch插件/编译栈；并非每个torch算子都必须经统一设备代理转发。

## 与device-context的对接

10-09核对两个版本：公共`dev-1.0@160ce4e`与设备方向`kistich/device-context@3d72ef3`。后者已有组件v0.3.0发布说明，但新增设备子树尚未全部进入公共分支。部署时固定双方确认的提交，不混用个人分支新契约和公共分支旧代码。

| 对接点 | 当前原型 | 后续衔接 |
|---|---|---|
| 设备初始化 | 经`runtime.use("ascend")`、`device_count()`、`set_device()`初始化；09-22实测使用服务器0916副本 | 锁定新的设备组件版本，核对实际导入路径与版本后回归 |
| 同步与流 | 适配器直接用`torch.npu.synchronize(x.device)`记录目标完成，是910C诊断路径 | 评估统一`runtime.synchronize(ordinal, timeout_ms)`及流接口；明确目标设备和有界等待，独立验证语义，不能只替换函数名 |
| 能力查询 | 当前设备/dtype/layout等规则在适配器内 | 设备能力消费后端声明；算子支持消费算子组清单，二者不能相互替代 |
| 错误 | 当前保留原异常并上抛，不做设备恢复 | 经`translate_error`取得分类及disposition，保留原因链交上层；不能自行按错误消息字符串决定恢复 |
| 服务启动 | 本方向尚未验证vLLM服务适配 | 复用`serve_standard.sh`；在实际模型worker生命周期安装/卸载适配，不另建服务启动脚本 |
| 环境 | 09-22锁定推理镜像及个人挂载源码 | 遵循公共ENV-SPEC与版本校验；总组确定基座，算子/编译版本变化单独留证 |

设备统一错误对象的L1–L4分类与本方向的三级回退是两套不同维度，不能按数字一一对应。设备组件的`handle_error`可能参与恢复编排，不作为算子调用失败后的默认处理；其契约仍注明在途任务入口未公开、`replay_tasks`为空，不能据此宣称自动任务重放或跨芯片恢复已完成。

参考：[设备接口约定](https://github.com/FlagRT/runtime-team/blob/3d72ef35a7ae98ee4d186dcf65f2a91235f0af32/dev/device-context/prototype/docs/INTERFACE_CONTRACT_DC_20260908.md)、[服务启动标准](https://github.com/FlagRT/runtime-team/blob/3d72ef35a7ae98ee4d186dcf65f2a91235f0af32/dev/device-context/prototype/docs/SERVICE_STARTUP_STANDARD_20260920.md)、[v0.3.0说明](https://github.com/FlagRT/runtime-team/blob/3d72ef35a7ae98ee4d186dcf65f2a91235f0af32/dev/device-context/prototype/RELEASE_NOTES_v0.3.0.md)、[公共环境规范](https://github.com/FlagRT/runtime-team/blob/160ce4e85950c123edfd53a97a06479c47378c54/dev/ENV-SPEC.md)。

## 三级回退定义

| 层级 | 判断条件 | 行为 | 实现状态 |
|---|---|---|---|
| 算子级 | 目标库未覆盖对应语义、未启用或未准入 | 不接管，保持合法原生路径 | 精确类型识别、白名单及禁用已验证；完整注册表待对接 |
| 实现级 | 算子存在，但候选不支持输入或版本条件 | 执行前筛选已验证实现；无目标可用时选合法原生，否则明确失败 | 当前一个FlagGems候选加原生；部分条件已验证，多候选与版本筛选待做 |
| 芯片级 | 整体芯片/框架后端/编译环境不兼容 | 启动前报告不兼容；由上层选择环境，运行后只能在安全任务边界恢复 | 设计阶段，兼容矩阵及恢复协议待跨方向联调 |

三级不是“执行失败后依次试三遍”。当前目标调用开始后，编译、执行、同步或输出契约错误均上抛。只有明确未提交计算、未修改状态等契约及测试成立，才可讨论安全重试例外。禁止单算子失败后自行跨芯片搬张量继续计算。

可选目标库缺失可按策略保留原生；库内部依赖损坏、ABI不兼容应显式报错。离线精度失败限制准入，不等于已实现在线精度回退。

## 注册与替换方案

优先消费已有注册机制，不预先要求算子组实现一套新API。映射至少需要语义标识、源入口与版本、目标签名、支持条件、原地/别名/梯度语义、验证状态及证据。

- 标准入口按完整契约接入；模型自定义入口需显式映射。
- 融合实现必须完整等价；不完整时保留原生，拆分另行评审。
- 安装前检查冲突，保留原调用；清理时仅恢复本人适配，不覆盖其他组件变更。
- 正式注册须独立验证作用域、递归、线程、compile/capture和worker生命周期。
- 路由记录区分selected、completed、error；当前native主要记录selected，不能把选择计数当成完成计数。

具体首批映射为`SiLUActivation.forward → flag_gems.silu`及`Qwen3RMSNorm.forward → flag_gems.rms_norm`。默认白名单为空，保守测试显式启用SiLU；RMSNorm实验不作为默认部署配置。

## 验证和实施顺序

1. 确认算子清单、接口、版本与精度要求，形成可追踪的对齐记录。
2. 校验统一基座和模型身份，先跑原生基线，再回归既有8组算子、4类回退、4组模型配置；15项CPU控制测试单独计数。
3. 对接注册/开关/恢复，补齐缺失实现、版本不兼容及执行错误的控制与实机证据。
4. 复用标准服务入口，验证vLLM真实worker中的代表算子或融合入口，不能复用Transformers成绩代替。
5. 具备目标后端与算子条件后扩展第二芯片、训练和兼容矩阵，与设备/调度联合验证启动拒绝及安全恢复边界。
