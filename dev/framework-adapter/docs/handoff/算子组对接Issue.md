## 希望算子组帮助确认的四个问题

### 1 有哪些算子能用 在什么条件下能用

希望获得现有算子清单及使用条件，先提供已有文档、表格或查询入口即可。

例如，我们要接SiLU，至少需要知道：调用哪个函数？支持昇腾还是昆仑芯？支持FP16、BF16中的哪些类型？对输入大小、维度和连续存储有没有限制？这些条件对应哪个版本？

这里说的“清单/注册表”，就是能查到这些信息的地方，不要求算子组重新做一个系统。先确认SiLU和RMSNorm的用法，同时提供已有全量清单，后续按模型需要逐步接入。

### 2 模型原来的调用应该怎样换成你们的实现

希望确认推荐的接入方式：是否已有注册或启用接口，让框架自动调用目标实现；还是需要我们找到具体入口，显式调用目标函数？如果已有开关，请提供启用、关闭和恢复的最小示例。

例如，当前模型用的是自己的`Qwen3RMSNorm.forward`，不是直接调用`torch.nn.functional.rms_norm`。因此，即使替换后者，也可能完全接不到模型实际调用。我们可以负责找入口，但需要共同确认它与哪个目标实现对应、参数和返回值是否一致。

融合算子也需要明确对应关系。例如，`SiLU-and-Mul`做的是`SiLU(x) * y`，不能只换成`SiLU(x)`；带残差相加的RMSNorm也不能直接换成纯RMSNorm。如果已有完整融合实现，请给对应接口；如果没有，我们建议先保留原生，是否允许拆开执行另行讨论。

还需要说明目标函数会不会修改输入、输出是否与输入共用存储，以及是否支持反向传播。这些行为不同，即使函数名相似，也不能直接替换。

### 3 能否在执行前知道不支持 报错后应该怎样处理

希望获得执行前可检查的规则，或已有的支持查询接口。查询本身不应修改输入或提交计算。

举例：假设某实现只接受连续存储的输入，遇到转置产生的非连续输入，我们可以在调用前识别并走原生。这个例子用于说明判断方式，不是在断言某个FlagGems算子实际不支持。

但“执行前知道不支持”和“执行到一半报错”不同：后者可能已经修改了输入或提交了设备计算，直接换成原生再算一次可能产生错误。因此还需要区分不支持、依赖缺失、编译失败和设备执行失败；若某种错误允许换实现重试，请说明保证条件。当前原型遇到目标执行异常会向上报告，不自动重算。

### 4 用哪个版本验证 怎样判断替换成功

希望提供推荐的算子库版本及配套编译、厂商环境版本，避免双方在不同组合上讨论同一个问题。

精度方面，需要共同确认与谁对比、允许多大误差，以及模型最终看什么指标。例如，我们的RMSNorm单次调用对照在当前容差内，但替换后模型隐藏状态超差、最终Embedding仍在容差内。这种情况能否接受，不能只凭“程序跑完”判断，需要算子组与精度、模型方向一起确定标准。具体数据见下节。

这次可以先回复已有材料的链接、SiLU/RMSNorm的推荐用法，以及尚待确认的问题和对接人；不要求一次性补齐所有算子的说明。

## 建议的替换与回退边界

以下是运行时侧建议，需双方确认：

1. 标准或自定义入口均先确认完整语义和支持条件，再安装适配。语义未知、目标缺失或显式禁用时，不接管原生路径。
2. 没有完整等价融合实现时先保留原生。拆分必须单独确认语义、精度、梯度和性能要求。
3. 当前原型只在目标执行前选择原生路径。目标调用开始后若报错，停止本次调用并向上层报告，不捕获所有异常后换实现重算。
4. 设备错误分类复用device-context；重试、任务重放和设备恢复由对应上层协调。错误处置建议不等于某个算子可安全重复执行。
5. 数值准入通过离线对照确定，不承诺线上每次双算或自动精度回退。

运行时侧负责入口适配、条件判断、开关恢复及调用证据；算子组确认目标实现契约和支持范围；精度/模型方向确认评价标准。若确认存在内核缺陷，由实现维护方处理。

## 具体问题 RMSNorm的模型替换差异

调用入口是模型中的 `Qwen3RMSNorm.forward`，不是 `torch.nn.functional.rms_norm`。目标调用保持同一输入、权重与epsilon：

```python
flag_gems.rms_norm(x, (x.shape[-1],), module.weight, module.variance_epsilon)
```

| 替换范围 | 两组输入的最后隐藏状态 | 最终归一化Embedding |
|---|---|---|
| 关闭接入或仅SiLU | 与原生一致 | 与原生一致 |
| 仅Q/K RMSNorm，56处 | 与原生一致 | 与原生一致 |
| 仅隐藏层及末尾RMSNorm，57处 | 两组超出当前诊断阈值 | 两组在当前阈值内 |

隐藏层替换两组最大绝对差分别为0.03125、0.0625，超差元素分别23/4096、1366/18432。当前诊断使用atol=rtol=0.005，尚非共同确认的验收标准。同输入旁路226次调用中30次非逐元素一致，但每次均在单算子容差内；不能据此断言目标内核错误，也不能以最终向量通过替代模型准入。

- 上述签名、维度、权重及epsilon是否符合推荐用法？
- 计算精度、归约及舍入允许哪些差异？是否有推荐版本或已知限制？
- 此场景应比较隐藏状态、最终向量还是下游任务指标，分别采用什么标准？
