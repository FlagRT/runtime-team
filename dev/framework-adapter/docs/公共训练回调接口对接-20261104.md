# 公共训练回调接口对接与本地验证

日期：2026-11-04。功能包本地候选0.3.0.dev4；本轮未提交或推送。

## 做了什么

把“从外面包装整个公共训练脚本”之外的另一种接法做好：启动器传入实际模型/训练配置和一个训练函数，适配包负责检查是否允许替换算子、执行训练、退出恢复，并返回结果报告。旧CLI继续保留。

这个接口能减少公共脚本更新时反复修改适配器的工作。实际模型、代码、依赖或训练参数改变时，仍需匹配对应审核。

## 给device-context的三项确认

1. 能否提供同步训练函数边界：设备初始化之后、模型创建之前进入适配器，整个前向/反向/优化器循环在回调内？默认仍走原生。
2. 实际模型路径、训练参数由公共入口解析一次，再同时用于身份采集和训练；相关代码/环境清单由哪份公共描述维护？
3. 原训练判据能否转换成`passed`结果；严格拒绝或执行异常时，停止其他rank及更新前步骤门控是否继续由公共启动器负责？

训练回调只运行一次；执行失败原样上抛，不在适配器内重跑训练或重置设备。输出路径每rank独占，调用方提供真实且运行期间冻结的身份/配置。确认后先联调现有910C Qwen配置，沿用关闭、开启和条件不满足三路判据。
