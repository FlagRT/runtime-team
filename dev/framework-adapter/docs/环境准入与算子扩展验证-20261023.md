## shmem 环境差异与处理

| 身份 | 27官方镜像 | 11训练v3 |
|---|---|---|
| image ID | 2e56022ae5b39930e6df12cbd69cece9156adf2a2a1136952f87c1ef0960315f | e13a15d0d02b86e9cd7b1656df3c6b52838c258f270b6b894a91c2b074da5f15 |
| Torch / torch_npu | 2.10.0+cpu / 2.10.0 | 同左 |
| Gems | 本人只读挂载f7ae8e6b934a33ec1ccaf2c9aae71edf205f8fb4 | 预装发行标记0.0.0+f7ae8e6b934a；安装目录内容另核hash |
| 编译发行包 | triton-ascend==3.2.1；同时有triton==3.5.0元数据 | flagtree==0.6.0+ascend.git15ec1a6c |
| 实际import triton | 模块3.2.0 | 模块3.5.1 |
| 实际模块路径 | /usr/local/python3.11.15/lib/python3.11/site-packages/triton | 同路径名，但内容不同 |
| shmem | 均未安装 | 均未安装 |
| TLE依赖路径 | 不包含triton.experimental.tle | TLE的communication.py第6行无条件import shmem |

关键不是“旧镜像有shmem、新镜像没有”，而是新编译器会走这条额外依赖路径。10-23无卡容器挂载只读驱动后，v3直接导入TLE复现`ModuleNotFoundError: No module named 'shmem'`；官方镜像无此TLE模块且本轮目标内核运行通过。Gems相同提交标记不能证明两种安装逐字节相同，但已有证据指向编译路径依赖，不能把此次失败归为算子精度问题。

公共[shmem case](https://github.com/FlagRT/runtime-team/blob/1d39898/dev/issues/shmem-missing/README.md)的源码链为`visit_For → import TLE → backends → communication → shmem`，与10-16真实SiLU编译失败栈吻合。本轮不重复已知失败内核、不安装未知shmem包、不用stub冒充修复。首次无驱动挂载的收数遇到libascend_hal缺失，修正为标准只读驱动挂载后才得到上述TLE结论；前者不是shmem判据。

处置分三种：

1. 需要继续验证目标实现：启动一项新的旧官方镜像实验，保留其精确编译器/Gems/模型证据。这是整项实验换环境，不是执行中换镜像。
2. 必须留在v3而允许原生：启动前禁用已知不兼容目标，明确记录known_compile_failure。已完成两条各3步小模型原生对照，loss和参数逐值一致。
3. 必须使用目标实现：启动前BLOCKED，等待总组/编译组提供经验证的构建组合。新包或镜像到货后，先冷缓存循环最小用例，再单算子前反向，再模型，不把旧资格复制到新环境。

此次差异审计使用[无卡收数脚本](../probes/inspect_compiler.py)；真实启动控制使用[训练v3单入口](../cases/ascend-train-v3/README.md#启动准入三路)。11预装Gems的内容身份为`package-sha256:3f88a35b57357813b06e355b7fa7f72bff741aa2858a003b87000dbf7091b52e`，2312个文件；没有伪造Git提交，也没有授予目标执行资格。

## FlagOP SDPA接入流程

固定源码[FLAG-OP/FlagOS-OP 79b1b1a](https://github.com/FLAG-OP/FlagOS-OP/tree/79b1b1aa867bd4dedd90eff69e6e9d717104e1fb/ops/sdpa)，本方向没有修改其算子内核。

`F.scaled_dot_product_attention → aten::scaled_dot_product_attention → register_a1的AutogradPrivateUse1注册 → _SDPA_A1_Function → triton_level按设备选ascend910 → Triton前向`。反向不是Triton backward，而是register.py里的FP32 ATen数学组合，最后转回输入dtype。

`impl="auto"`是另一条路：它patch Python层F.sdpa，不做上述ATen注册；默认大序列无mask可能选择native，因此“进入auto接口”不等于命中目标。两种机制不能不加区分地混用。保存注册前的Python函数对象，也不保证绕过之后被改写的ATen dispatcher。

本轮先在独立worker直接调用固定版本的autograd包装，以避免改动全局注册。两组FP16方形输入的前向最大差均为0，数学反向最大差分别0.00048828125和0.001953125，满足对方op层示例所用atol=rtol=0.02。该阈值只用于此候选对照，不是后续模型的统一精度标准；还不能把私有类调用当稳定公开接口交付。

### 需要算子组确认的四件具体事情

| 事项 | 本轮证据 | 希望确认或补齐 |
|---|---|---|
| 支持条件 | dropout要求0；非方形causal在源码中被`Sq == Skv`关闭。CPU隔离反向测得最大差约2.0；全遮罩行的数学反向产生NaN | 将这些输入列为暂不支持并给清晰限制，或由实现方修复并补前反向测试；初期运行时仅考虑方形、无mask、dropout=0子集 |
| 可直接调用的训练接口 | 当前测试使用私有`_SDPA_A1_Function.apply`；裸Triton前向不能等同于完整autograd接口 | 推荐一个稳定的公开前向+反向包装入口及参数/返回契约，便于运行时在调用前选择目标或原生 |
| A1默认参数与撤销 | 不传counter时直接注册Function.apply，普通三参数调用在Torch 2.10/2.12 CPU注册控制中缺5个参数；`unhook_a1(lib)`只删形参，调用者仍持lib时dispatcher未恢复 | counter可选分支需一致填默认参数；明确支持的注册/释放生命周期及最小测试。NPU直接候选通过不覆盖这些注册行为 |
| 可复现环境与命中 | 环境锁写triton3.5.1，但不足以区分实际发行包/路径；auto接口内部可能选native | 给实际编译器构建、导入路径、Gems身份和逐平台前反向证据；复用现有catalog，不另要一套新算子清单 |

测试入口：[CPU包装层复现](../probes/audit_flagop_sdpa.py)、[NPU限定候选](../probes/qualify_flagop_sdpa_npu.py)。CPU脚本用原生前向替身隔离真实数学反向，不是在CPU上运行Triton内核。发现预期缺陷时输出FAIL/退出1；环境不满足或未复现预期边界时为ERROR/退出2。全局注册实验结束即退出独立进程，不把测试中的私有_destroy当产品恢复接口。

SDPA后续接入策略是：由运行时在注册前检查条件；不合格直接原生；合格调用稳定目标包装；目标运行异常终止worker。接口明确后再做限定attention路径三路对照，不优先于公共搜广推模型扩展；暂不把SDPA加入已发布的通用开关，不使用“异常后再调一次F.sdpa”的递归退路。

## 代码增量与安全边界

功能代码位于独立framework-adapter仓：

- startup.py：可选依赖可用性、已知失败环境、Git/安装包内容身份、严格目标策略。身份采集不是资格签发。
- config.py：schema 1保持兼容；schema 2增加require_target。损坏配置/证据仍报错，不能当无资格吞掉。
- bridge.py：tanh共享SiLU/sigmoid接入机制；补Tensor.sigmoid/tanh入口。严格模式的out等不支持签名在原生写入前拒绝。
- training.py/train_cli.py：上游验收回调通过后才写PASS；未提供回调时明确标scope-only。严格模式需观察所选算子前反向命中，空命中不能算成功。
- 本地57项控制覆盖默认关闭、缺包保留原生、严格阻断、预装包身份变化、未资格输入、异常停止、两个组合模型和原有行为。

可选提供方的导入失败可能已经改变进程状态，因此不在原worker里捕获后继续native。执行异常、反向异常和恢复异常同样停止；本轮注入验证失败步不执行optimizer更新，但不承诺回滚已有梯度、模型缓冲、随机数状态或设备状态。双rank单侧失败联动退出还需后续专门验证。

每步比较预测、loss、17个梯度、28个模型状态及Adam状态，共98个张量；目标判据atol=1e-5、rtol=1e-4，关闭/缺资格要求完全一致。保留确定性模式和相同步内随机种子，没有修改模型、优化器或容差来获取PASS。

两种batch的预测最大差均1.4901161e-8、loss差0。首个失败为`mlp.mlp.0.bias`：batch32有347/400元素超阈值，最大差0.001923628；batch16为334/400、0.001942478。离线对全部保存张量复查，超阈值仅位于三层BatchNorm前Linear bias。batch32首层bias梯度差最大7.5996e-7，166个元素符号不同；代入首步Adam公式`p0 - 0.001*g/(abs(g)+1e-8)`，重建参数与实测差≤7.46e-9。batch16对应重建残差≤1.87e-9。证据支持“近零梯度差被Adam放大”，不能据此直接判定Gems内核错误或业务质量下降。

处理：DeepFM暂保留原生，当前本地`records-final.json`为空；历史review仅用于重现失败，不作为模型准入。单算子通过不能自动升级为整个模型训练通过。此处失败是optimizer更新后验收发现的数值偏差，不是执行异常自动回退，更不具备参数回滚能力。
