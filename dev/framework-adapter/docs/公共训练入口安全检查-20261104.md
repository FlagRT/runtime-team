# 公共训练入口：旧审核失效与严格启动拒绝

日期：2026-11-04。功能包固定为已发布dev3源码[40864f9](https://github.com/FlagRT/framework-adapter/tree/40864f9ac266163a80e323ca1abe082bb6b8a2f9)。本轮补充测试与证据目前在本地，未追加推送。

## 结果

两类安全检查共4个双rank场景通过：旧审核不能沿用到变化后的训练配置/运行时代码；必须使用目标算子的严格模式在条件不满足时，直接拒绝进入训练。

| 场景 | 保持不变/唯一变更 | 结果 |
|---|---|---|
| 学习率变化，允许原生 | 相同模型、算子、运行时代码、审核；LR从1e-5改为2e-5 | 旧审核不匹配，两rank各3步原生训练通过；各84次原生SiLU，0目标调用 |
| 学习率变化，严格模式 | 同上，仅require_target=true | 两rank均BLOCKED，原因workload_unverified，0训练步骤、0算子调用 |
| 缺少模型审核，严格模式 | 使用原1e-5配置，workload_reviews=null | 两rank均在训练前拒绝，0训练步骤、0算子调用 |
| 运行时代码版本变化，严格模式 | 在本人运行时副本增加1个未导入的Python版本标记文件 | 实测settings身份变化，旧审核不匹配，两rank均在训练前拒绝 |

每条严格路径都检查：进程非零退出、两份BLOCKED报告齐全、拒绝原因正确、算子计数为空、步骤为0、hooks已恢复、没有上游训练结果。仅非零退出、超时、被杀、缺一个rank或其他异常均判失败。新增6项证据检查器CPU测试，总计14项通过。

版本测试验证的是运行时源码身份变化，不涉及升级实际torch/编译器包。逐字段核验表明：学习率场景只改变optimizer.lr；版本场景只改变runtime_files中的标记文件；缺审核场景的模型与训练身份完全保持原值。

## 执行入口

沿用[case启动器](../cases/ascend-official-unary/assets/run.py)的dc-train阶段及正常安装包CLI。新增参数：

```sh
# 学习率变更；配置使用schema3、enabled=true、require_target=false，保留旧审核
python assets/run.py <环境与挂载参数> --stage dc-train \
  --training-config unqualified --training-config-file /配置/lr-native.json \
  --training-lr 2e-5 --output /新的结果目录

# 严格模式；require_target=true，必须得到两rank完整的启动拒绝证据
python assets/run.py <环境与挂载参数> --stage dc-train \
  --training-config on --training-config-file /配置/on.json \
  --training-lr 2e-5 --training-expect-blocked --output /另一个新目录
```

命令中的环境参数按本case README准备，必须重查卡及模型路径。完整实际Compose和环境参数见[baseline/demo](../cases/ascend-official-unary/demo/20261104-public-safety/README.md)，机器结果见[摘要](evidence-public-safety-20261104/summary.json)。
