# 资格验证与审核流程

此流程是本地原型的准入边界，不是自动认证系统。资格记录不能从环境探测结果自动生成passed。

## 两条路径必须分开

1. 正常调用：环境及输入准入→已审核能力记录→实验目标调用；缺记录保留原生。执行后错误上抛停止，不换原生重试。
2. 首次资格实验：独立一次性进程，在明确协调的设备和核验的环境中测候选实现；输出原始数据，交人工审核。不写正常调用的配置，不给业务训练自动开绿灯。

旧SiLU探针`probes/test_silu_training_npu.py`不带`--scoped-adapter`时是raw注册诊断，不经过正常适配准入；只能在独立资格实验使用。它不是模型默认入口，更不能作为shmem绕行方法。新公共包的生产调用没有“忽略准入”参数。
10-18新增独立入口probes/qualify_unary_npu.py，SiLU/sigmoid各6组真实前反向资格实验通过，并经执行者核对填写本轮实验记录。具体范围见[实测报告](910C公共适配器实测-20261018.md)，不套用SiLU证据替代sigmoid，也不自动推广到其他环境。

## 首次实验前的检查单

- 重新核对允许使用的主机、本人容器、空卡、单卡映射、磁盘容量；限时独立进程，失败后不继续模型训练。
- 使用公共baseline工具核对镜像/挂载来源。记录镜像ID、torch/torch-npu、Triton/编译器构建、Gems提交及实际加载路径、runtime版本、源码hash和未提交状态。
- 源码覆写/运行时补丁意味着新的环境；不能沿用同镜像ID的旧资格。宿主驱动/CANN、额外PYTHONPATH与挂载由运行方baseline另核；当前7字段Environment不是所有外部依赖的完整指纹。
- 已知训练v3的编译缺shmem保持阻塞。不为取得passed加stub、安装未知包、扩大阈值或反复触发同一失败；先等可核验的新支持组合。
- 该精确失败镜像的SiLU有内置否决：即使配置误填passed也返回known_compile_failure。移除此限制必须有新的修复证据和代码审核，不通过CLI临时忽略。

## 每条实验记录的最小证据

精确算子及前反向接口、dtype/shape/layout/开关；同输入原生与目标的输出和梯度、原定容差、实际目标命中日志；退出前后dispatcher一致、恢复后原生对照；异常路径停止/无重试。
训练使用前向及反向都通过的记录，不能拿仅前向或CPU模拟冒充训练资格。模型短轨迹通过也不等于长训练数值准入。
现有容差FP32=1e-5、FP16=5e-3、BF16=3e-2保持不变；若某算子需要另定标准，应向算子组确认并单独记录，不能为当前失败放宽。

## 审核后如何接入

审核者把结果文件复制进独立证据目录，确认结论与支持范围，再填写JSON配置。schema为1，records为数组，每条包含：

- environment：chip、torch、torch_npu、gems_revision、image_id、triton、compiler_build，必须与实测一致；
- operator、dtype、shape（正整数数组）、stages（forward/backward）；
- evidence（同目录内相对文件路径）、evidence_sha256；
- status（passed/failed/revoked/unknown）、revision（当前为1）。

JSON加载器校验字段和文件哈希，不评判实验结论，也不提供权限认证；配置来自受信任审核者。正常启动器通过`--admission-records`显式加载。精确环境/输入匹配、两个阶段已通过且revision相符时，才允许显式experimental替换；匹配failed/revoked记录优先否决。
证据更改或缺失导致加载失败，停止启动而不是静默批准。代码准入规则变化时提高revision，旧记录不自动沿用；撤销记录保留审计原因与原始证据，不删失败历史。

## 当前结论

通用准入、本地包及10-18精确旧官方环境的SiLU/sigmoid硬件验证完成；本轮实验记录不是生产批准。训练v3仍受shmem阻塞，更多模型/平台及完整三级回退未完成。
