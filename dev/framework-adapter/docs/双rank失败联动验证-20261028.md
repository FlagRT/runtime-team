## 机制判断与下一步

现有适配包的单进程边界成立：异常上抛、不重试原生、恢复注册。torchrun能终止其余worker，但不能把进程最终退出当成训练步的提交屏障；公共入口依次调用梯度all_reduce、clip_grad_norm、optimizer.step，缺少本方向要求的更新前全rank确认。

下一步在训练集成层增加明确的步骤协议：更新前确认每个rank前反向及通信成功；任一rank报错、失联或超时，阻止所有rank进入optimizer，再由监督进程统一退出。控制通道不能复用可能已失配/阻塞的梯度集合通信。先与device-context确认集成位置，再在独立framework-adapter包实现并重跑相同三组。此项不是算子组的数值修复，也不是直接改公共脚本或盲目增加一次同组barrier。

本轮不新增功能包代码，只用既有测试入口完成硬件验证；7项CPU判定及6项case检查重跑通过。故障注入在目标注册作用域内抛出Python异常，覆盖的是此故障类别，不代表驱动硬故障、断电、参数回滚或完整三级回退。
