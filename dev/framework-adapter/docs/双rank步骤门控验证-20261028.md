# 双rank训练步骤门控验证（2026-10-28）

## 结论

在27机、旧官方昇腾镜像、物理设备0/1上，新增单机双rank更新前门控后，Qwen3-Embedding-0.6B公共训练入口的正常、前向故障、反向故障三组检查通过。功能代码在独立framework-adapter仓，公共训练脚本和算子内核未改。全部材料尚未提交推送。

这是对[同日修补前失败](双rank失败联动验证-20261028.md)的后续：此前单侧报错后，对端仍进入一次optimizer.step；本轮两种注入均阻止了双方optimizer调用。并非数值问题修复，也不等于完整三级回退。

| 场景 | 两rank参数更新调用 | 结果 |
|---|---|---|
| control | 各3次，各完成3步 | PASS；每rank真实Gems SiLU前向84次、反向84次 |
| forward：rank0目标前向抛错 | 各0次 | 安全判据PASS；注入后9.56秒退出 |
| backward：rank0目标反向抛错 | 各0次 | 安全判据PASS；注入后6.60秒退出 |

两种故障均没有进入梯度集合通信、没有原生重试或worker重启；两个rank均完成钩子清理，worker均已退出。故障场景的训练报告FAIL、worker返回1是预期失败停止；外层result.json为pass表示安全判据通过，不是故障训练成功。

## 机制与范围

1. 独立包`step_guard.py`在当前固定训练入口外设置作用域钩子。
2. backward完成并同步设备后，两rank确认均已成功，才允许进入后续梯度通信。
3. optimizer.step之前同步设备，再确认双方已就绪，才放行参数更新。
4. 任一rank捕获异常，通过同机共享本地目录发布ABORT；对端检查后抛错停止。等待超时也拒绝继续。
5. 每次启动使用独立输出目录和torchrun运行标识，拒绝旧rank目录或跨运行标记；退出恢复钩子。

只支持当前固定的单机两rank、eager、Tensor.backward、在作用域内创建的AdamW入口。独立错误通知不依赖HCCL梯度通信。测试仍使用随机token、FP32、batch1、seq32、AdamW、3步，不是业务数据长训练。

不承诺：跨机/NFS、多优化器/梯度累积等任意训练循环、驱动死锁恢复、更新放行之后的原子回滚。已放行的更新遇到后续故障，仍需checkpoint恢复协议。本轮未验证训练v3目标内核，也未解决shmem。
