# 公共训练入口：模型审核与三路回归

2026-11-04完成实测；dev3源码与制品身份见[发布审查](dev3发布审查-20261104.md)。

## 做成了什么

把模型身份和审核机制接到彬哥现行公共训练脚本：启动时实际读取模型文件和训练设置，只有模型审核、算子资格、环境与输入同时匹配才启用替换。不是另写训练程序，也不是把以前的工作缩成“只支持DeepFM”。

本轮在11机910C官方镜像，用Qwen3-Embedding-0.6B权重通过AutoModelForCausalLM进行双进程、两设备短训练。新增模型审核，沿用SiLU替换；RMSNorm没有新增替换。原有P800 DeepFM和其他模型的限定结果仍保留。

## 实测结果

| 测试 | 结果 |
|---|---|
| 关闭 | 两进程各3步；各84次原生SiLU，原因experimental_disabled；目标调用0 |
| 开启但缺模型审核 | 两进程各3步；各84次原生SiLU，原因workload_unverified；目标调用0 |
| 独立原生重复 | 每进程1,863项损失/梯度/参数对照，共3,726项逐值一致 |
| 独立候选资格 | 每进程1,863项、共3,726项通过既定atol=1e-5、rtol=1e-4；最大绝对差9.5367431640625e-7；各84次真实SiLU前向和84次反向 |
| 取得本轮审核后的正式开启 | 正常schema 3 CLI通过；两进程各3步、各84次真实前向和84次反向，目标必需模式启动审核通过；不使用资格探针的测试插桩 |

1,863项 = 3步 ×（1个loss + 310个同步/裁剪后梯度 + 310个更新后参数）。不包含优化器状态张量，不是1,863个不同算子。原生保存不计比较数；资格实验与三条正式路径不重复算模型覆盖。

各正式路径公共训练检查均为6/6，步骤门控完成3步且恢复；两进程采集的模型身份一致。原生和目标三步loss保留四位小数均为17.0600、16.3875、14.4921，数值判断使用完整张量而非这个四舍五入曲线。带插桩/编译的吞吐不用于性能比较。

## 工程变化与审核

- 功能包增加public_entry.py，实际解析DC_MODEL并哈希权重、配置、公共runtime/适配包Python源码和相关训练设置，输出workload_rankN.json。固定新版入口强制schema 3；旧schema不能在新版入口绕过模型审核。旧入口兼容路径保留，不篡改历史验收。
- 本地标准模型、只读输入、单机两rank；自定义/远程auto_map代码拒绝。当前CLI仍限ascend/hccl，不自动扩成P800双卡支持。
- 集成case接受独立配置目录；正常CLI无“跳过模型审核”选项。资格探针单独运行，先产生数据，再由执行者审阅并填写[本轮实验审核](../cases/ascend-official-unary/review-public-20261104/model-reviews.json)。不是算子组签字或生产批准，不能改模型名称复用。
- 初轮离线安装包109项CPU控制；补充新版CLI拒绝旧配置测试后独立重建110项通过，11个运行时Python文件与实测wheel相同。另8项case控制通过。发布依赖锁已对齐dev3，重建和实测wheel的11个运行时文件一致。

## 环境问题和边界

27先试物理2/3，关闭路径在set_device/aclInit阶段报507899、Resource_Busy，尚未进入训练，不能归为算子或回退失败，也未仅凭报错认定“固定容器名额”。本人容器已停，未停他人容器。随后换11，最小原生计算成功，再跑上述闭环。

11两次准备失败分别为sudo票据、Docker包装器未传递Compose变量；修复仅涉及本人启动包装器和本进程Git配置，没有跳过strict基线检查、修改宿主全局Git配置或公共镜像。失败记录保留。

这是旧官方镜像成功，不是训练v3/shmem已修复；不是完整三级回退、新框架或跨芯片恢复验收。数据为合成token，只证明有界训练的接入和准入，不宣称业务训练效果。P800 Qwen/OneRec历史失败配置没有因此解除。
