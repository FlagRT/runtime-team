状态：本方向设计基线草案，供总组、算子组及相关方向评审；不是已批准跨组接口。已实现范围以第六节为准，不表示三级回退全部完成。本文收敛09-21行动要求、现有原型及09-22实验，不新增验收数量承诺。

## 一、目的与边界

在约定框架/模型入口，让已验证的统一算子库实现优先执行；算子未覆盖或支持条件不符时，在提交设备计算前保持同设备原生实现；环境整体不兼容时，由上层在启动或完整任务恢复边界选择兼容环境。

不承担算子内核重写、任意自定义算子自动识别、设备后端重做，也不把“捕获所有异常后再算一遍”作为安全回退。原生实现不是无条件成功的兜底：其自身错误仍需报告。

FlagGems提供目标算子实现；Triton/FlagTree构建物是编译依赖，不是同一层的备用算子。编译栈不兼容不能用进程内任意切换版本解决。当前实测未引入FlagTree构建物。

## 二、层级与交互

```text
启动/恢复阶段：任务管理 → 设备能力与环境版本检查 → 选择兼容环境或拒绝启动
                                               ↓
运行阶段：模型/框架入口 → 本方向入口适配与执行前选择
                         ├─ 已准入且满足条件 → FlagGems等目标实现
                         └─ 未覆盖/禁用/条件不符 → 同设备原生实现
执行结果或错误 → 结构化记录 → 调用者 / 监控 / 上层任务管理
```

这是逻辑关系，不是每层部署一个服务。算子接入在执行模型的worker同一进程内，不通过RPC搬张量；设备上下文提供身份、流/事件和错误等接口，不要求每个torch算子绕行一次设备代理。

| 部分 | 职责及交互方式 |
|---|---|
| 框架/模型入口 | 保留参数、返回结构、原地/别名及梯度语义；优先已有扩展点，必要时使用受控补丁 |
| 实现清单 | 提供语义对应、调用入口、支持条件和版本；优先复用算子组已有注册能力 |
| 选择策略 | 查询开关、准入与支持条件；每次选择一个实现，不先执行再碰运气 |
| 设备上下文 | 提供环境及设备能力；流、事件和错误接口按设备方向约定对接 |
| 任务管理 | 接收环境不兼容或执行失败；决定请求失败、进程重启或完整任务恢复 |
| 监控与精度 | 消费路由/错误证据、制定评价标准；不在每次线上调用中双算全部结果 |

当前接入是特定Qwen模块实例的eager作用域补丁，不是“全局注册为框架默认实现”已经完成。正式全局注册、vLLM融合入口和训练入口必须分别核对生命周期及语义。

## 三、三级回退的具体含义

这三层不是每次错误都依次尝试的三条执行路径。芯片层检查通常先发生在任务启动时；算子/实现层判断发生在调用提交前。

| 层级 | 判断对象与触发条件 | 动作 | 当前状态 |
|---|---|---|---|
| 算子级 | 没有语义匹配的注册项，或策略未启用该算子 | 不接管，保持该框架同设备原生路径 | 精确类型识别、白名单及禁用已实现；完整注册表对接待做 |
| 实现级 | 已知算子的候选实现不满足dtype、shape、layout、梯度或已验证版本条件 | 过滤候选；选已验证的另一实现，否则保留原生；没有合法路径则报告不支持 | 现原型仅一个FlagGems候选加原生，验证了部分前置条件；多候选与版本筛选待做 |
| 芯片级 | 当前芯片/框架后端/编译栈与任务所需能力不兼容 | 启动前返回原因和兼容环境建议，由上层分配；运行后恢复必须从安全的完整任务边界重启 | 方案阶段，兼容矩阵接口及跨方向联调未完成 |

不承诺从一块芯片把某个失败算子的张量直接搬到另一块芯片继续跑。新环境需重新建立上下文、加载状态并保证任务语义；调度、检查点及多卡一致性由相关方向共同负责。

### 错误处理规则

| 场景 | 处理规则 |
|---|---|
| 显式关闭、未准入、输入条件不支持 | 目标执行前走原生，记录原因 |
| 可选目标库本身缺失 | 在明确允许native模式时保持原生；现原型识别 `ModuleNotFoundError.name == flag_gems` |
| 目标库内部依赖损坏、ABI/版本导入异常 | 显式报错；不能一概伪装成“算子不支持” |
| 编译或目标调用抛错、同步报错、输出契约错误 | 现原型上抛，不在当前调用内重跑；未来仅在有明确未提交/无副作用契约时评审例外 |
| 离线精度对照失败 | 暂不准入相关实现/用途，保留复现并交确认；不是线上自动误差回退 |
| 设备失效、显存不足、分布式rank失败 | 向上层报告；不自行reset、清空他人任务或单rank改走CPU |

当前RMSNorm就是离线A/B发现差异后，保守配置不启用RMSNorm。不存在“检测到模型超差后自动恢复原生重新算”的已实现机制。

## 四、注册清单与兼容矩阵：请算子组提供什么

09-26已将对外问题集中到[算子组对接主Issue](算子组沟通-接入与安全回退对接需求-20260926.md)，本节保留设计侧所需信息；双方确认后再同步更新，不将草案视为上游已承诺接口。

接受现有Python注册API、清单、表格、测试或文档链接；本方向补齐映射，不要求算子组重建一套系统。下面是待确认的信息，不是已要求其他组交付的新接口。

| 信息 | 最少需要确认的内容 | 用途 |
|---|---|---|
| 语义标识与对应关系 | 算子名、框架入口/已知别名、是否融合；同名但不同语义要区分 | 判断能否替换，别名不等于等价 |
| 调用契约 | 函数签名、参数默认值、返回结构、out/inplace/alias、输入是否会被修改 | 编写适配和恢复逻辑 |
| 支持条件 | 厂商/芯片、dtype、shape、stride/layout、轴、epsilon等参数限制 | 提交设备前筛选候选 |
| 数值与梯度 | 计算/累加精度、cast次序、误差标准、反向和高阶梯度支持情况 | 离线准入及训练范围判断 |
| 运行方式 | 当前流规则、异步错误、编译/capture限制及可预先检查的错误 | 确定安全执行与上报边界 |
| 版本与构建 | 算子库commit、Triton/FlagTree分支或构建物、插件/SDK/框架版本 | 避免把不同环境成绩混用 |
| 验证资产 | 推荐测试入口、参考实现、已知问题与支持负责人 | 建立联合回归及问题闭环 |

首批对接：SiLU、RMSNorm。请同时给出已有完整可用算子清单，结合目标模型调用情况分批选择，不将本方向永久范围限定为这两个。

当前映射：`SiLUActivation.forward(x)` → `flag_gems.silu(x)`；`Qwen3RMSNorm.forward(x)` → `flag_gems.rms_norm(x, (x.shape[-1],), weight, eps)`。SiLU-and-Mul不等于SiLU，带残差/原地更新的融合RMSNorm不等于当前纯RMSNorm，不能仅改名字就替换。

兼容矩阵建议记录：芯片/驱动、厂商torch后端、框架/模型入口、算子库commit、编译构建物、dtype/shape/模式范围、状态、证据及日期。状态区分“已验证”“未验证”“已知不支持”“阻塞”；一个版本点通过不外推整个版本区间或整家芯片。当前唯一可引用模型准入范围是09-22的910C FP16 eager SiLU保守配置，RMSNorm为未准入实验，BF16/其他模型/其他芯片不能填通过。

## 五、执行流程与可观察性

1. 启动时采集环境身份和实际框架/模型入口，核对可用实现；后续接入版本矩阵，不把未知条件视为已支持。
2. 只对已知且无冲突的入口安装适配；保存原生调用。已有forward覆盖、嵌套安装、未知签名等拒绝接管。
3. 调用前按开关、算子准入和支持条件做选择，保持原输入/返回语义；不悄悄改dtype、复制布局或迁移设备来制造“支持”。
4. 执行单一实现；当前目标实现前后同步仅用于诊断完成证据。正式异步/多流方案必须另测，不照搬同步开销作为性能结论。
5. 退出作用域或异常清理时恢复本人安装的入口，不覆盖其他组件后续变更；服务集成应在worker正确生命周期完成，不能只修改客户端对象。

已有记录：op、backend、reason、stage、shape、dtype、device及代表模块名，区分目标selected/completed/error。现代码对native主要记录selected，不能称每条native都有completed记录；事件样本有界，计数单独保留。

后续拟补：实现/环境指纹、策略版本、任务关联及全路径完成事件；与监控方向对齐格式，不另建一套性能采样工具。不在日志中保存权重、输入激活、凭证或请求正文。
