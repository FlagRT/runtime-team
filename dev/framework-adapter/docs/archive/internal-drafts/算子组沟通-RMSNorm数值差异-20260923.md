## 一、问题与希望确认的结论

在910C、FP16、Transformers eager下，将Qwen3-Embedding-0.6B中的原生 `Qwen3RMSNorm.forward` 替换为同一版本的 `flag_gems.rms_norm`，调用和设备执行可以完成，但模型最后隐藏状态相对原生超出当前诊断阈值。最终归一化Embedding仍在阈值内。

按位置拆分后，仅替换注意力Q/K归一化的两组输入均与原生完全一致；仅替换隐藏层归一化（含末尾norm）可复现隐藏状态超差。当前默认不准入RMSNorm，保守示例只启用SiLU。

需要确认：这种差异是否符合该实现的数值契约？模型替换应采用什么参考实现和误差标准？是否存在更合适的调用接口或已知版本限制？本反馈不预判FlagGems内核算错，也不要求逐位一致；不通过放宽现有阈值把失败改成通过。

## 三、实际入口与怎么替换

不是拦截 `torch.nn.functional.rms_norm`。本版本模型使用自己的 `Qwen3RMSNorm` 类，原型只对已知精确类型的模块实例临时替换forward，保存其原生绑定方法，退出作用域恢复；不做全局ATen注册。

调用对应关系如下，完整实现见[适配器源码](https://github.com/FlagRT/runtime-team/blob/2aad264/dev/framework-adapter/probes/qwen_scoped_adapter.py)：

```python
# 原生：保存的 Qwen3RMSNorm.forward(x)
# 目标：沿最后一维归一化，使用同一输入、权重和epsilon
y = flag_gems.rms_norm(
    x, (x.shape[-1],), module.weight, module.variance_epsilon
)
```

替换前检查开关、白名单、推理模式、设备、dtype、连续布局、权重及epsilon条件。目标执行前后同步NPU，检查输出shape/dtype/device，记录selected/completed/error。执行异常直接上抛，不转原生重跑。数值差异由外部A/B测试发现，不是线上自动精度检测或自动回退。

只替换Q/K或隐藏层的实验使用同一个 `flag_gems.rms_norm` 接口，改变的是选中的模块位置，不是更换FlagGems版本。也不能仅据此断言内部调度到同一个具体kernel。

## 四、问题复现与关键结果

代码固定在 `runtime-team@2aad264`。最短模型复现入口是[qwen_rms_ablation.py](https://github.com/FlagRT/runtime-team/blob/2aad264/dev/framework-adapter/probes/qwen_rms_ablation.py)：对同一模型分别只替换Q/K和隐藏层归一化；进一步定位用[qwen_rms_shadow.py](https://github.com/FlagRT/runtime-team/blob/2aad264/dev/framework-adapter/probes/qwen_rms_shadow.py)，在原生路径同输入上旁路对照，不改变模型输出。

环境准备及可执行命令集中在[本周原型复现说明](本周原型复现说明-20260923.md)第四节A、E、F；也可直接查看已发布的[实验报告第5、8节](https://github.com/FlagRT/runtime-team/blob/2aad264/dev/framework-adapter/docs/910C模型接入与安全回退-20260922.md)。算子组不需要复跑无关控制测试来理解本问题。原实验依赖服务器0916设备原型副本，不承诺任意新机器只拉镜像即可复现。

期望观察：分组结果中Q/K两项 `within_tolerance=true`、隐藏层两项为false。诊断退出0或 `status=completed` 仅表示收集完成，不代表数值全通过。

比较规则：FP16诊断使用逐元素 `abs(actual-native) <= 0.005 + 0.005*abs(native)`。这是现有测试阈值，不是算子组已批准的验收标准。

| 替换范围 | batch1最后隐藏状态 | batch3最后隐藏状态 | 最终Embedding |
|---|---|---|---|
| 关闭接入 / 仅SiLU | 与原生一致 | 与原生一致 | 均一致 |
| 全部RMSNorm（113个） | 超差 | 超差 | 两组在阈值内 |
| 仅Q/K（56个） | 与原生一致 | 与原生一致 | 两组一致 |
| 仅隐藏层及末尾（57个） | 最大差0.03125；23/4096元素超差 | 最大差0.0625；1366/18432元素超差 | 两组在阈值内 |

- 分组4个模型实验中2个通过、2个隐藏状态失败，不能报成4个全通过。
- 旁路226次RMSNorm调用中196次逐元素一致、30次非一致；每一次仍在当前单算子容差内。这是调用次数，不是226个独立用例。
- 另测“单位权重归一化后乘真实权重”“FP32归一化后转回FP16并乘权重”两种诊断组合，仍有相同数量的非一致调用；它们不是新部署策略。
- 随机输入/权重的8组独立算子用例通过，不证明真实模型全替换可用。CPU FP64分阶段舍入参考也不能据此裁决哪一方必然正确。
- Q/K两组短输入通过不足以扩大准入；数值原因尚未定位到某条内核指令、归约或编译优化。
