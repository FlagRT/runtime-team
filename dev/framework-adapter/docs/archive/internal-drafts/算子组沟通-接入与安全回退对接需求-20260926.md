## 一、背景与本次希望对齐的内容

我们负责框架侧的算子接入、实现选择和安全回退，希望在支持条件满足时优先调用统一算子库，否则保留合法的原生路径。目前在910C上完成了Qwen3-Embedding-0.6B的SiLU接入及基础回退验证，RMSNorm调用已接通，但隐藏层替换存在数值差异。

继续扩展算子和模型前，需要明确可用算子清单、调用/注册接口、替换与融合处理规则、错误边界及精度要求。可以直接复用已有注册机制、API文档、测试或表格，不要求算子组另建一套系统，也不要求一次性补齐所有算子。

当前验证限FP16、PyTorch+Transformers eager，不据此声称vLLM、Megatron、全部芯片或三级回退已完成。实验与代码见[已发布报告](https://github.com/FlagRT/runtime-team/blob/2aad264/dev/framework-adapter/docs/910C模型接入与安全回退-20260922.md)。

## 二、请提供或确认的材料

| 对齐项 | 具体问题 | 可以提供什么 |
|---|---|---|
| 算子清单与支持范围 | 哪些实现可用，哪些待验证/不支持？对应哪些框架入口、芯片、dtype、shape、布局及参数范围？ | 现有清单、注册查询入口或支持矩阵，注明版本与已知限制 |
| 调用规范 | 参数顺序/默认值、返回结构、out/inplace/alias、输入修改及梯度行为是什么？ | 函数签名、语义说明、最小调用示例和测试 |
| 注册与生命周期 | 推荐直接调用、框架注册、插件还是补丁？开关作用于全局、线程还是模型？如何退出恢复，如何避免重复注册与递归？ | 推荐机制、安装/卸载示例、与其他插件共存限制 |
| 替换对应关系 | 框架标准算子、模型自定义实现和目标实现如何对应？同名但不同语义如何区分？ | 已确认的入口/别名/语义映射；未知项允许明确标注待确认 |
| 融合处理 | 是否有完整等价的融合实现？若无，是否允许拆分，适用哪些语义和模式？ | 融合接口及组成操作说明、拆分限制和验证案例 |
| 支持查询与错误 | 能否在执行前无副作用地判断支持？不支持、依赖损坏、编译失败、设备执行失败如何区分？ | 查询API或规则、错误分类，以及是否已提交执行/修改输入的保证 |
| 精度与验收 | 参考实现、容差和模型评价标准是什么？如何处理单算子通过但模型输出不同？ | 现有精度测试规范、已知差异、需精度/模型方向共同确认的事项 |
| 版本与构建 | 推荐哪个算子库commit、Triton/FlagTree构建物、厂商插件及SDK组合？ | 可复用版本记录/锁文件、兼容限制与维护联系人 |

对接清单建议至少能回答：语义标识、调用入口、支持条件、版本、验证状态和证据位置。字段名及存储格式由双方按已有机制确定；不在此预定一个新的注册接口。

首批以SiLU、RMSNorm对齐并验证方法，同时请求现有完整清单，再按目标模型需求分批扩展。两个首批算子不代表最终范围只有两个。

## 三、替换及融合算子的处理原则（本方建议，待确认）

| 遇到的入口 | 建议处理 | 需要共同确认 |
|---|---|---|
| 框架标准算子 | 语义和支持条件匹配后，通过推荐扩展点接入 | 参数/返回、梯度和原地行为等是否一致 |
| 模型自定义算子 | 显式识别版本和入口，建立语义映射后适配 | 谁维护映射，模型更新时怎样回归；不能按类名相似直接替换 |
| 有完整等价实现的融合算子 | 按完整融合契约替换 | 组成操作、返回值、残差、原地更新、别名、计算精度和反向行为 |
| 没有等价实现的融合算子 | 当前保留原生，不自行拆分 | 如需拆分，先确认合法性和数值/性能要求，再作为独立方案验证 |
| 语义或支持条件未知 | 不准入目标实现，保留可用原生路径并记录缺口 | 补充说明与验证后再扩大准入 |

例如，SiLU-and-Mul不能只换成SiLU；带残差或原地更新的融合RMSNorm不能直接套纯RMSNorm接口。此处是一般处理原则，不能据此认定当前Qwen3RMSNorm问题由融合导致。

建议分工：算子组确认目标实现语义及支持范围，运行时侧实现入口适配与选择逻辑，精度/模型方向共同确定验收标准。拆分后是否值得启用需另做同条件性能评估，本次不承诺性能收益。

## 四、回退边界及需要的协作

- 算子级：目标库未覆盖或未启用该语义时，保持框架原生路径。
- 实现级：算子已知但当前实现不支持输入/环境时，在执行前筛选已验证候选；无合适目标则保留合法原生路径。
- 芯片级：整体环境不兼容时提供不兼容原因/支持条件，由设备及任务管理方向在启动或完整任务恢复边界协调。算子组提供能力约束，不承担跨芯片迁移调度。

上述为设计边界，不表示全部实现。详细设计见[三级回退方案v0.1](三级回退方案与算子接口需求-20260923.md)。

本方当前保守规则：执行前确认不支持才回退；目标调用开始后抛错默认上抛，不捕获所有异常后盲目重算。若某种失败可安全改用其他实现，需要明确“未提交设备、未修改输入/状态”等契约和验证证据。依赖损坏、设备失效不能统一当作不支持；原生路径自身也可能失败。

数值准入通过离线验证确定。发现模型精度差异后可以收紧白名单，但不宣称实现了每次调用在线双算和自动精度回退。
