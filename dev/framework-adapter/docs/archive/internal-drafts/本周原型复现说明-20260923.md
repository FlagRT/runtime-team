## 二、接入实现与运行条件

本轮链路：文本 → Transformers加载Qwen3模型 → PyTorch模型forward → 实例适配器选择FlagGems或保存的原生forward → torch_npu / 910C。镜像带vLLM，但本轮没有启动vLLM服务，也没有验证Megatron、训练或融合算子。

| 模块入口 | 目标调用 | 本轮策略 |
|---|---|---|
| `SiLUActivation.forward(x)` | `flag_gems.silu(x)` | 保守模型实验显式启用；每次模型前向28次目标完成 |
| `Qwen3RMSNorm.forward(x)` | `flag_gems.rms_norm(x, (x.shape[-1],), weight, eps)` | 默认保留原生；仅在专门实验显式启用，113个模块/前向 |

适配器只识别精确类型，默认白名单为空，不全局替换ATen。检查开关、准入、推理状态、设备、dtype、布局及RMSNorm参数后，才执行目标；目标前后同步NPU以记录完成。目标执行错误上抛、不重跑。原生调用保留原有签名，退出作用域恢复本人补丁。

离线数值不通过后限制准入，不是在线检测误差后自动回退。诊断同步/CPU拷贝不用于评价性能；当前结果不证明通用多线程、多流、compile或生产服务安全。

- torch 2.10.0+cpu、torch-npu 2.10.0、Transformers 5.5.3；Triton 3.5.0、triton-ascend 3.2.1。`+cpu`是包版本标记，NPU由torch_npu提供。

## 三、具体测了哪些内容

### 3.1 独立目标算子：8组，不是8种

| 算子 | batch1来源形状 | batch3来源形状 |
|---|---|---|
| RMSNorm隐藏层 | `[1,4,1024]` | `[3,6,1024]` |
| RMSNorm Q | `[1,4,16,128]` | `[3,6,16,128]` |
| RMSNorm K | `[1,4,8,128]` | `[3,6,8,128]` |
| SiLU | `[1,4,3072]` | `[3,6,3072]` |

形状来自模型探针；独立测试使用固定seed=22的随机输入/权重，不是真实模型激活。每组比较原生与FlagGems、确认completed路由、输入/权重未变，以及退出后原生重放一致。8组均通过；不能据此推断所有真实模型输入都通过。

### 3.2 真实NPU执行前回退：4类

关闭开关、算子未准入、FP32输入不在当前策略内、转置后的非连续输入。每类确认选择原生、没有FlagGems路由、结果与原生一致。FP32未准入是本原型策略，不是FlagGems不支持FP32的结论；不是4种设备故障注入。

### 3.3 模型开关与RMSNorm诊断

- 保守测试：两组输入各跑关闭、仅SiLU两种模式。4配置隐藏状态/向量均与原生完全一致，退出后的模型重放也一致。
- 完整替换实验：增加SiLU+RMSNorm、仅RMSNorm模式。均可执行，但两组输入的隐藏状态超差；不能只看最终向量在阈值内就报通过。
- 同输入旁路：hook观察原生输入/权重，分别跑FlagGems及两种诊断组合；hook返回None，不替换模型结果。检查原生输出、输入和权重未被修改，记录逐层统计。
- 分组实验：56个Q/K、57个隐藏层及末尾norm分别替换，使用同一FlagGems接口。Q/K两组完全一致；隐藏层两组分别23/4096、1366/18432元素超差，最大差0.03125、0.0625。仅这两组通过不能准入所有Q/K场景。

FP16现有诊断阈值atol=rtol=0.005，不是算子/精度方向已批准标准。未放宽阈值、未修内核；精度差异的交接问题见独立Issue。

### 3.4 CPU控制与不占卡检查

15项CPU控制包含：CPU/关闭两种原生恢复情形，白名单、梯度走原生、默认不启用、已有覆盖保护、嵌套拒绝、异常退出恢复、参数错误透传、跨线程拒绝、未知类/非法白名单拒绝，以及缺库、内部依赖损坏、目标部分写入后报错不重跑。最后几项通过mock控制条件，不等于硬件故障实测。

12项元数据测试与15个Python/4个shell语法检查为另外的本地检查；不能替代上述适配器功能或NPU模型测试。09-23没有在本机重跑15项CPU控制（缺torch/transformers/pytest），引用的是09-22测试记录。
