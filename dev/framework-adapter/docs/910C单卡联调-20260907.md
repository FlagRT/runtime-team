## 实际完成的开发

1. **补齐 CachedOp 热路径**：带输入约束的实现每次重新检查，不把第一次输入的选择永久用于后续输入。
2. **禁止不安全重试**：声明 `runtime_fallback_safe=False` 的实现异常后直接抛出，且不把它加入失败黑名单导致下一次悄悄跳过。
3. **修复参考 Rotary**：interleaved 系数展开方式修正；遵守 inplace=True/False 的输入修改约定。
4. **修复原生 Rotary**：原 `_npu_rotary_embedding` 路径在同进程混合精度、改变 cos/sin 表时暴露异常或数值错误，改用 `npu_rotary_mul`，并适配 interleaved 布局和输入写回。新增执行前输入范围检查。
5. **修复 FlagGems Rotary 非连续输入**：执行前连续化，要求原地操作时将结果写回原张量。

第 4 项的底层缓存根因尚未完成源码级定位，不能将现象表述为所有版本的 ATB 都有此问题，也不能说 BF16 硬件不支持。
最终实现没有屏蔽 BF16：替换原生调用入口后 FP16/BF16 都通过了当前矩阵。

## 验证结果

最终常规异步模式复测：**275 项 dispatch 单测通过，74 项真实 NPU 集成测试通过，无跳过**。
日志见 [最终测试目录](evidence-20260907/final-checks/)。先前失败日志也保留，不能把旧失败轮次与最终结果混在一起统计。

| 真实测试 | 覆盖 | 数量 |
|---|---|---:|
| SiLU-and-Mul | FlagGems / Ascend native / torch reference；FP16 / BF16；输入 (1,128)、(7,512) | 12 |
| RMSNorm | 三种实现；FP16 / BF16；有 / 无 residual；输入 (7,128) | 12 |
| Rotary | 三种实现；FP16 / BF16；Neox / interleaved；inplace 开 / 关；连续 / 非连续；Q=(7,4,64)、K=(7,2,64) | 48 |
| 输入条件切换 | 测试注入行数条件，实际执行 FlagGems → native → FlagGems，结果与 CPU 公式比较 | 1 |
| 内置注册及范围检查 | 不注入能力规则；native → reference → native 的实际调用序列，包含 FP32 的执行前选择 | 1 |

数值参考是 CPU 公式，FP16 atol/rtol=0.005，BF16=0.03；这是小规模功能阈值，不是项目最终精度指标。
Rotary 额外检查输出别名、原输入不变或正确写回。单测中的部分写入异常用受控 Python 函数注入，不会故意制造 NPU 硬件错误。

## 完整引擎冒烟

`probes/tiny_vllm_smoke.py` 在本地生成随机权重的微型 Llama（2 层、hidden=256、4 个 Q head、2 个 KV head、vocab=128），不下载模型。
vLLM 单卡 eager 模式完成加载、预填充、4 token 解码和退出。
日志确认 RMSNorm、Rotary 使用 `vendor.ascend`，SiLU 使用 `default.flagos`。
另一次复测加载 strict=true 配置，不允许执行异常后的重试。

最终 strict 模式下同一组随机权重与 CPU Transformers 贪心解码对照：两者都输出 `[122,122,122,122]`，4 token 一致，见 `evidence-20260907/tiny-model-cpu-compare.log`。
这只是一个短输入的 token 级对照，不等于 logits 全量精度或模型级验收。

此测试不是训练，不代表正式模型质量、正式模型覆盖或性能达标；首次 Triton 编译时间不能当作稳定推理性能。
