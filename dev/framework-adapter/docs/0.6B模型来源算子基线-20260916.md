## 模型和测试方法

模型为 Qwen3 结构，28 层，hidden=1024、intermediate=3072，Q/KV heads=16/8，head_dim=128，RMSNorm eps=1e-6。读取真实权重，不是随机模型。

`probes/qwen_embedding_baseline.py` 使用 Transformers AutoModel，显式诊断 eager、关闭 KV cache；通过 module pre/post hooks 观察原生模块，不替换其 forward。按算子/shape/stride/dtype/eps 去重，记录第一组实际输入，随后直接调用该模块的 forward 重放。CPU 参考、输入/权重不变及 dtype/device 检查均通过后才记 pass。

2 组输入分别为 1 条和 3 条短文本，token shape `(1,4)`、`(3,6)`；输出 `(1,1024)`、`(3,1024)`。last-token pooling 正确处理左右 padding，归一化结果为有限值且范数接近 1。未测检索质量、同义语义阈值、长文本或服务吞吐。

本轮明确选用 CPU FP32，atol/rtol=2e-5；后续 FP16/BF16 预设 0.005/0.03 尚未取得本轮 NPU 结果。所有结果都带设备字段，禁止混用。

## 实测结果

| 层次 | 数量 | 结果与说明 |
|---|---:|---|
| 探针控制逻辑 | 12 | 本地通过；不导入 torch，不计为设备/算子测试 |
| 模型 CPU FP32 前向 | 2 组 | batch=1/3，输出向量 shape、有限性、范数检查通过 |
| RMSNorm CPU 代表用例 | 6 | hidden、Q norm、K norm 三类输入，各覆盖两组 batch/token 形状 |
| SiLU CPU 代表用例 | 2 | 两组真实 MLP 激活输入 |
| 模型 NPU 前向/算子用例 | 0 | 最终探针停在设备初始化，不计为用例失败覆盖 |

6 组 RMSNorm 输入为 `(1,4,1024)`、`(1,4,16,128)`、`(1,4,8,128)`，以及对应 `(3,6,...)` 三组；2 组 SiLU 为 `(1,4,3072)`、`(3,6,3072)`。本轮实际采集的输入都是连续布局。

两次模型调用观察到 226 次 Qwen3RMSNorm module 调用、56 次 SiLUActivation module 调用。这是调用次数，不是 282 个独立测试，更不是底层 kernel 数。只对去重后的 8 组做数值/副作用/重放验证。CPU 参考最大绝对误差为 0，不代表半精度或其他后端也无误差。

首版和后续修正版重复运行的同一批用例不累加；最终结果以 `cpu-float32-v3.json` 为准。

## 对接入开发的直接影响

1. 真实 Transformers 模型中的 `Qwen3RMSNorm.forward` 使用 FP32 平方均值、rsqrt、类型转换和乘 weight 展开计算，不调用 `F.rms_norm`。因此历史 `PreferGems` 只拦截 `F.rms_norm` 并不能自动接入这个模型；后续需评估模块入口或框架已有替换入口，不能只扩大测试数字。
2. RMSNorm 不只有 `[tokens,1024]`：Q/K norm 的末维是 128，并带 head 维度，输入规则要覆盖实际布局，不能只按 hidden size 写死。
3. 镜像内 vLLM-Ascend 源码的 SiLU-and-Mul 路径使用融合 `torch_npu.npu_swiglu`，RMSNorm 有独立融合/残差语义。这里仅做源码核对（文件哈希已留存），尚无 vLLM 运行观测，不能与本轮 Transformers 的普通模块混用。
4. 当前锁定推理镜像未查到 FlagGems。若后续方案需要引入，先登记依赖和基座差异，再确认接入位置；本轮未擅自安装。

## NPU 阻塞及探针修正

最终 v3 经统一 runtime 的 ascend 后端初始化时，device_count=0，`runtime.set_device(0)` 报 `aclInit 507899 / Resource_Busy`。宿主同期 dmesg 记录 `uda_occupy_dev_by_ns: Conflict open udevid`，目标 udevid=0，访问命名空间与占用命名空间不同。

已确认单设备节点及只读驱动挂载存在。宿主设备没有计算进程不等于可分配给新容器；该证据说明存在设备访问的命名空间占用冲突，但尚未识别占用者或证明唯一根因，不能只归因于显存、镜像版本或“3 个容器”上限。

首版和 v2 探针在关闭自动加载时过早构造 `torch.device("npu:0")`，先报未知设备名：公共 runtime 的 `use()` 仅选择懒加载后端。最终改为 device_count 触发插件加载、set_device 后再构造设备对象，并补充懒加载顺序及失败不回退测试。前两版的探针错误与 v3 的真实设备初始化错误分开保留，不混计。
