# 框架接入与安全回退 · 9 月任务规划与接口草案

## 1. 本阶段做什么

依据 [阶段目标 v1](../../../docs/运行时层原型验证-战略目标-910C.v1.md) §5「调度」第 3 项，交付统一框架接入与多级安全回退方案，本月不改变推理框架默认行为。9 月 9 日周会要求各方向将状态、启动/测试入口和具体任务集中到自己的目录；本方向下一步围绕 `Qwen/Qwen3-Embedding-0.6B` 做实际算子路径核对与原生基线。

当前三件事：弄清模型实际调用哪个实现；整理它能接受的输入与语义；明确将来接入优化实现时如何执行前选择、如何让不安全错误上抛。不是另写一套算子库，也不是直接往公共推理镜像安装旧插件。

本方向不替代设备管理、多卡通信、训练任务重启、动态 Batch 或性能报告方向。TensorFlow/ONNX Runtime、多芯片兼容和全局默认注册保留为后续范围，不在本月宣称交付；其他平台探索可单列推进。

## 2. 基座与调用链核对

以 [stack.lock.910c.v1.yaml](../../stack.lock.910c.v1.yaml) 为环境事实源，不在本方向另锁一套镜像。以下是需要核实的链路，不是本方向新实测结果：

- 推理腿：官方 vLLM-Ascend 镜像中的 Embedding 服务 → 模型层/融合算子 → 厂商 PyTorch 扩展及算子实现。设备入口复用 `runtime.use("ascend")`，不要求 vllm-plugin-FL 参与。
- 训练腿：锁定训练镜像中的模型与训练脚本 → PyTorch → `torch_fl` 例外后端。其导入顺序与环境变量遵守锁文件，不与 `torch_npu` 混装。已有 NPU eager 接入原型没有验证这条路径的训练/反向能力。
- 公共原型入口：[device-context/prototype](../../device-context/prototype/README.md)，服务验证脚本在 `runtime/proto/proto_infer_serve.py`；复用之前先读其使用条件，不另起重复服务或在他人服务上注入故障。

首轮记录至少包括镜像实际 ID/digest、包版本、模型本地路径与 revision（能取得时）、设备后端、默认启动参数、附加依赖，以及调用形态（eager/编译或融合）。不能只凭 pip 安装列表证明模型调用了某个库。

周会允许按需补依赖后收拢公共基座；因此确有缺包时记录包名、版本、原因和安装差异，提交总组处理，不私自升级公共核心栈。当前公共文件中的训练 transformers pin 与镜像分发待办仍须跟踪。

## 4. 算子核对与测试范围

优先 SiLU 类、RMSNorm 类，因为已有小输入验证可作参考；但必须根据模型实际执行路径调整：

- `F.silu` 不等于融合 `silu_and_mul`。融合入口应检查门控维度与拆分方式，不能以单独 SiLU 通过代替融合算子通过。
- `F.rms_norm` 不等于含 residual 更新的融合 RMSNorm。要记录 eps、weight、残差有无、返回结构及原地写入/别名语义。
- Python 模块或函数命中只证明该入口被调用；若要确认底层实现需源码注册链或相应 trace 证据。不能从模块名称推断所有底层 kernel 都已被替换。
- 输入大小优先来自实际模型记录，不把历史 `(1,128)`、`(7,512)` 小输入冒烟称为模型覆盖。FP16/BF16 只测该镜像与模型实际支持的组合，不静默转换精度来规避失败。
- 数值用同设备原生实现及 CPU FP32 参考作对照；误差阈值提前登记，并与精度方向确认模型相关要求。CPU 仅是离线测试参考，不是运行时迁移目的地。
- 同时检查 dtype/device、输入与权重不变、必要的 residual/别名约定。同步探针用于功能定位，不能作为异步正确性或性能达标证据。

在锁定推理环境先只做默认路径观察和原生测试。若后续需要开启 FlagGems 注册、改入口或做异常注入，先作为单列实验确认范围，不对当前验收服务默认生效。

## 5. 接入与安全回退接口草案

这一节是待评审的数据与行为约定；尚未新增公共 Python/C++ API，也未接入调度/监控生产流程。

### 5.1 拟记录的信息

- 环境身份：镜像标识、框架/后端/库版本、设备类型；环境缺失时不声明支持。
- 调用元数据：算子及 schema/融合入口、shape、dtype、stride/layout、device、inplace/residual、是否需梯度；不保留张量内容或模型权重。
- 候选能力：实现 ID、适用条件、支持/不支持/未知、原因。检查只读元数据；未知按未准入处理，不把设备执行失败当作能力探测手段。
- 路由记录：本次输入、候选被排除原因、选中实现、是否真正开始执行、异常阶段。`selected` 不能代表成功，主机调用返回也不自动代表设备执行完成。

上述字段拟提供给调度/监控/性能方向；具体结构和下游消费方未确认，先保留在本方向记录中。

### 5.2 安全行为

1. 执行前选择：优化实现不支持当前输入、包未安装或无已验证组合时，允许交回同设备的原生入口；非法输入仍由框架报错。原生入口必须明确，不能再次进入相同注册包装造成递归。
2. 实现执行后失败：默认原样上抛，不自动换实现再算一次。尤其是原地写入、残差更新、异步提交和通信之后，输入或设备状态可能已经改变。
3. 注册生命周期：未来若采用作用域注册，要验证退出与异常退出后恢复、嵌套/并发策略以及与其他注册机制的冲突。现有 FlagGems 退出恢复测试不等于这些组合全部通过。
4. 芯片级问题：记录完整异常、调用位置和环境，对接设备方向的分类与恢复接口；本层不自行 reset 设备、不跨芯片搬数据、不重放训练步骤。
5. 跨流正确性：事件依赖决定数据能否安全读取，内存生命周期保护与事件依赖不能相互替代。沿用 device-context 契约并联调；不能用无条件同步的测试证明生产异步路径正确。

原需求的“算子级、实现级、芯片级三级回退”在本月方案中分别讨论未覆盖算子的原生路径、候选实现选择、设备不可用时的上层处置；不是承诺三层都已具备透明自动重试。设备错误分类给出的 `retry/replay` 建议也不能单独证明某个已执行算子可安全重跑，还需上层确认可恢复状态与重放边界。

设备接口参照 [设备上下文章节](../../device-context/prototype/docs/INTERFACE_CONTRACT_DC_20260908.md)。本方向目前只有约定对接，尚未完成实际调用联调。

## 6. 已有资产与差距

- [PyTorch 同步原型](PyTorch独立接入-20260907.md)：68 项历史测试；仅 Python eager 作用域、`torch_npu`、推理优化路径。不是 ATen 全局注册，不覆盖 compile/融合路径及训练后端。
- [vLLM 原型](910C单卡联调-20260907.md)：275 项单测、74 项 NPU 测试；改动在独立 vllm-plugin-FL 仓，补丁在本方向留存。官方 vLLM-Ascend 不因此自动获得这些改动。
- [多芯片探索](多芯片环境与算子验证-20260909.md)：平头哥 24 组、壁仞 BF16 4 组通过；昆仑芯尚无可用算子环境。都不是统一模型验收。
- 当前旧 vLLM 原型的 `runtime_fallback_safe` 默认值、`resolve()` 绕过输入检查、PyTorch 同步开销及异步互操作，均是后续评审项，不能在方案中略去。

不在本节点承诺：生产性能收益、全算子覆盖、全局默认替换、所有异常可重试、多框架训练支持、多芯片无感迁移。
