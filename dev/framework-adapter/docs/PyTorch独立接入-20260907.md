# PyTorch 独立接入原型（2026-09-07）

## 本轮范围

在 27 机既有单卡容器里验证普通 PyTorch eager 程序，不导入 vLLM 或 vllm_fl。
复用 `flag_gems.silu` / `flag_gems.rms_norm`，不新写算子内核，不修改驱动或公共配置。
环境仍为 torch 2.10.0+cpu、torch_npu 2.10.0、FlagGems 5.3.5、Triton 3.5.1、CANN 9.0.0。

该原型放在本方向 `probes/`，用于确定接入规则与测试要求，尚不是新增的正式子库。

## 机制与使用

使用 PyTorch `TorchFunctionMode` 对作用域内的标准 Python 接口做选择：

```python
import torch
import torch.nn.functional as F
import torch_npu
from pytorch_eager_adapter import PreferGems

x = torch.ones(3, 128, device="npu", dtype=torch.float16)
with torch.inference_mode(), PreferGems() as adapter:
    y = F.silu(x)                  # 支持的输入优先 FlagGems
    z = F.silu(x.float())          # FP32 暂不在加速范围，调用原生接口
print(list(adapter.routes))
```

`nn.SiLU` 和 `nn.RMSNorm` 内部调用上述函数，因此无需修改层代码。
退出作用域后恢复普通调用；不同线程不自动继承该作用域；禁止嵌套本原型的作用域。
路由记录是有界列表，不保存张量。`selected` 只表示选中，不能当作成功记录。
当前对每次加速调用在前后执行 NPU 同步，保证原型以保守同步方式验证；有明显开销，不能据此做性能结论。

已有 `flag_gems.use_gems` 通过 `torch.library.Library("aten", "IMPL")` 注册实现。本轮没有重做那套注册机制，也没有修改 ATen 全局默认实现；先用作用域验证输入约束和错误处理，后续再决定如何将这些规则并入正式注册路径。
机制依据已安装 PyTorch 的 `TorchFunctionMode` 源码/文档和 FlagGems 5.3.5 的 `use_gems`、`silu`、`rms_norm` 实际源码。

## 输入选择与错误处理

| 情况 | 行为 |
|---|---|
| 普通 NPU 张量、FP16/BF16、非空且连续、无所需反向图 | 尝试 FlagGems |
| RMSNorm 单个末维归一化，weight 存在且 shape/dtype/device/布局匹配 | 尝试 FlagGems；eps=None 转为输入 dtype 的机器精度 |
| CPU、FP32、非连续、空张量、inplace=True、需要梯度、关闭开关 | 执行前选择 PyTorch 原生入口，设备不变 |
| RMSNorm 没有 weight、多维归一化或 weight 不匹配 | 执行前交回原生接口；非法参数仍由框架报错 |
| FlagGems 包本身未安装 | 执行前选择原生入口 |
| FlagGems 依赖损坏或已选择的实现抛出异常 | 直接抛出，不尝试再次执行原生算子 |

需要梯度时原生 SiLU 和 RMSNorm 的梯度已有测试；这不是 FlagGems 反向支持的验证。
不是把 NPU 数据搬到 CPU 回退：CPU 只用于测试的数值参考。
不与外部全局算子替换、其他 Mode 或 `flag_gems.use_gems` 混用；这种组合下原始函数可能已被其他机制覆盖，当前不承诺其路由含义。

## 测试与限制

最终同步原型 **68 项测试连续两轮全部通过**（8 项控制逻辑/CPU 测试、60 项 NPU 测试）；独立 nn.Sequential 示例两轮通过，路由为 RMSNorm→FlagGems、SiLU→FlagGems、FP32 SiLU→native，且没有导入 vLLM。
这些计数不能与上一轮 vLLM 方向测试混称为同一套框架测试。

测试文件为 `probes/test_pytorch_eager_adapter.py`，覆盖：

- F 函数与 nn 层；FP16/BF16；输入 (1,128)、(7,512)；RMSNorm eps=None/1e-6。
- 原生结果和 CPU 浮点公式双重对照，FP16 atol/rtol=0.005，BF16=0.03。
- 输入不兼容的执行前选择、输入变化时重新判断、梯度、原地语义、线程与作用域恢复。
- 模拟部分写入后抛错，确认不再次执行；可选包缺失与依赖损坏分别处理。
- 在测试进程结束时确认没有导入 vLLM/vllm_fl。
- 对 RMSNorm 增加多种固定种子和输入、权重、原生输出不被覆盖的检查。

第一轮以及一次复测出现 RMSNorm 单个元素差异（FP16、eps=None）。双重对照显示那轮 FlagGems 结果符合 CPU 公式，而留存的原生输出出现偏差。
隔离测试、全新 Triton 缓存测试及插入快照同步后的测试通过。不能由此断定是哪一层的 stream、内存生命周期或算子实现造成问题。
因此最终原型显式同步加速调用前后的 NPU 工作，并增加“测试不插入中间同步”的原生→FlagGems→原生回归；没有放宽误差阈值。原始失败日志保留。
**异步互操作根因仍未解决，当前只按同步诊断原型交付；恢复异步及用于生产性能优化前必须单独验收。**

本轮不包含 `torch.compile`、export、TorchScript、ATen 直接调用、Tensor 子类、多设备、多进程及性能验收。
SiLU 并不等于自动识别并融合 `silu_and_mul`；PyTorch 没有统一的 Rotary 标准入口，本轮也没有自动接入 Rotary。
这是第二个框架调用场景的原型，不是 TensorFlow/ONNX Runtime 已经完成，更不是全局默认替换已交付。
