## 本轮审查与补强

dev2相对已发布dev0新增厂商/设备接口身份及schema 3模型审核。审核需匹配模型文件、训练设置、环境与算子组合；failed/revoked优先于passed，未知条件不授予目标资格。模型通过也不能覆盖单算子失败。执行后目标异常停止，不盲目原生重试。

本轮未发现需修改运行时代码的发布阻断问题；补充6项CPU负向/边界测试：准备后环境变化仍拒绝、模型通过不覆盖环境已知失败、严格拒绝不进入训练、审核证据损坏不启动、不命中目标不能冒充严格成功、关闭时无需目标provider/审核。包测试由94项增至100项。构建快照同时改为包含完整docs，便于离线追溯接口说明。

明确兼容变化：旧七字段昇腾JSON可由load_records读取；Python Environment的torch_npu关键字/属性已改为backend_version，旧关键字调用需迁移，不能将JSON兼容宣称为所有Python API兼容。七个位置参数仍表示旧昇腾身份；P800必须显式声明kunlunxin/cuda。

模型文件哈希是可信启动器采集并传入的输入约定，不是安全认证/远程证明。本case已做实际身份采集，公共双rank CLI尚未接齐；缺身份不能据此取得模型目标资格。

## 复现

在具备Python、torch及本地构建依赖的CPU环境，检出上述精确提交：

```sh
python tools/build_local.py --output /absolute/new-build
python /absolute/new-build/source/tools/build_local.py --output /absolute/new-rebuild
python audit.py --repo /absolute/framework-adapter \
  --build /absolute/new-build --rebuild /absolute/new-rebuild \
  --hardware-wheel /absolute/historical-dev2.whl \
  --case /absolute/runtime-team/dev/framework-adapter/cases/kunlun-unary \
  --output /absolute/new-audit.json
```

audit.py位于本报告相邻证据目录。历史wheel不是仓库下载附件；没有该制品只能复现构建与CPU测试，不能声称独立复核了历史负载一致性。本轮环境为macOS arm64、Python 3.10.20、torch 2.12.0，其他版本见摘要。构建使用no-index/no-deps，不自动安装或替换厂商torch。
