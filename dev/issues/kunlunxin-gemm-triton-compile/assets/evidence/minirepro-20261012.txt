## 3) OutOfResources 形态的包装点（triton/backends/xpu/compiler.py:362-367，镜像内实读）
   
           try:
               pm.run(mod, 'make_ttxir')
           except Exception as e:
               from triton import OutOfResources
               raise OutOfResources(0, 0, f"uni_sram {e}")
   

   -> 该 except 把 pm.run('make_ttxir') 抛出的**任何**异常一律包成 OutOfResources，
      消息里的 Required: 0, Hardware limit: 0 是构造函数里写死的零，并非真的资源不足；
      e 的原文是 "PassManager::run failed"。误标会把排查引向「调小 block size / num_stages」。

## 4) stage 注册顺序（同一文件 581-585，镜像内实读）：两种形态是同一路径的两个阶段
           stages["ttir"] = lambda src, metadata: self.make_ttir(src, metadata, options)
           stages["ttxir"] = lambda src, metadata: self.make_ttxir(src, metadata, options)
           stages["llir"] = lambda src, metadata: self.make_llir(src, metadata, options)
           stages["elf"] = lambda src, metadata: self.make_elf(src, metadata, options)
           stages["xpubin"] = lambda src, metadata: self.make_xpubin(src, metadata, options)
   -> ttxir 有 try/except（上面 3），llir 的 pm.run 没有 -> LLVM 原生断言不可捕获 -> abort()
