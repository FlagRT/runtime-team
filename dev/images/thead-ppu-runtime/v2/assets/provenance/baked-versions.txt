## 3. ⚠️ 两个"看起来通过"的坑（后人最容易踩）

### 3.1 `pip show triton` 是**空的**
   triton 目录是 **flagtree wheel 内部的一段**，不是独立安装的 distribution
   ⇒ 镜像里没有 `triton-*.dist-info`，`pip show triton` 无输出。
   后果：用「pip show triton 有没有输出」判"装没装"会判错（判成没装），
        用「pip freeze 里有没有 triton」做版本比对同样不成立。
   正确判据：`python3 -c "import triton; print(triton.__version__)"`（实测 3.6.0）
            + 派生层 wheel 的 sha256（assets/provenance/flagtree-wheel.sha256）。

### 3.2 `flagtree.__version__` 自报 **3.6.0**，而 pip 元数据是 **0.7.0+ppu.gite223f42c**
   实测：`python3 -c "import flagtree; print(flagtree.__version__)"` → 3.6.0
        `pip show flagtree` → Version: 0.7.0+ppu.gite223f42c
   原因：该字段跟随 triton 版本线（3.6.0），不是包版本。
   后果：拿 `flagtree.__version__` 当版本锚会误读。版本锚一律用 pip 元数据 + wheel sha256。

## 5. 派生层的两条构建指令（docker history --no-trunc 前两行）
RUN |1 SP=/usr/local/lib/python3.12/site-packages /bin/sh -c pip install --no-index --no-deps \
    --no-cache-dir /tmp/flagtree-0.7.0+ppu.gite223f42c-cp312-cp312-linux_x86_64.whl && rm -rf /tmp/flagtree-...
RUN |1 SP=/usr/local/lib/python3.12/site-packages /bin/sh -c python3 -c 'import importlib.util as u, sys; \
    missing=[m for m in ("triton","flagtree") if u.find_spec(m) is None]; \
    sys.exit("FATAL: 派生层缺失 " + ",".join(missing)) if missing else ...'

读法：**第 2 条是构建期自验证**（find_spec 缺失就让 build 失败），所以"镜像能建出来"
本身就等于"triton+flagtree 都在"。它不能替代运行期判据（能 import ≠ 能编 kernel），
运行期判据见 assets/evidence/。
