## 失败定位与修复对照

| 同一 100 轮探针 | 数值校验（两端合计） | 组销毁 / 退出 |
| --- | --- | --- |
| 原镜像原库 | 1599/1600，1 次 BF16 P2P 失败 | 已销毁；因数值失败退出 1 |
| 公开源码 + 两项历史补丁 | 1367/1600 | free invalid pointer，两个 Rank SIGABRT |
| 加借用流所有权修复 | 1414/1600 | 组销毁完成，无该 SIGABRT；数值仍失败 |
| Host wait + 仅延长 AllGather 临时张量存活的试验 | 1460/1600，剩余均为 AllGather | 组销毁完成；未将该中间方案交付为最终修复 |
| 最终 Host wait + AllGather 复制前后同步 | 1600/1600 | 两端销毁，启动器退出 0，无超时/强杀 |

流析构问题：插件把成员中的借用 ACL 流地址交给 `streamDestroy`，
后者销毁底层流并 `free` 包装地址。0003 改为 `streamCopy` 分配包装、`streamFree` 只释放包装，
不销毁运行时持有的底层流。

完成语义问题：仅向流插入等待不等于 Host 等待结束；0004 的 CANN `Work.wait()`
增加通信流同步。AllGather 的 CANN stream guard 不切换张量运行时流，
因此在 HCCL 后、copy-back 前等待通信流，并在临时扁平缓冲释放前完成设备同步。
“只延长张量存活”不足以消除本次错误；最终采用明确的保守同步方案。
当前结果证明该组合通过所测范围，不证明所有异构路径或候选镜像的问题全部关闭。

## 扩展矩阵与跨流

原库和最终修复库分别执行，均得到以下结果：

| 验证 | 参数与计数口径 | 每个库的结果 |
| --- | --- | --- |
| 通信矩阵 | 2 Rank × FP32/BF16 × 8/1024/65536 元素 × 20 轮 × 4 操作 | 960/960，max abs diff 0 |
| 跨流消费 | 同样 Rank/dtype/尺寸/轮数，每轮一个 async AllReduce + Event 消费对照 | 240/240，max abs diff 0 |
| 退出 | 每个 Rank 记录 group_destroyed，外层检查启动器退出 | 均退出 0 |

四类操作为 AllReduce SUM、AllGather 列表、双向 Send/Recv、async AllReduce。
矩阵保留输入缓冲到完成，显式同步生产与消费；输入随轮次变化，避免只检查固定常量。
三档最大消息为 FP32 256 KiB / BF16 128 KiB，不代表大规模带宽测试。
960 是逐 Rank 操作校验数，不是 960 个独立场景，P2P 一个校验包含发送和接收。

跨流路径在生产流提交异步规约并 wait，记录 Event，消费流等待 Event 后读取，
中间不插入全设备同步；消费结束后做 Host 对照。
最终补丁的 wait 本身为 Host 阻塞，故该证据证明正确消费，不证明异步重叠收益。

## Event 与训练

[生产 Event 实机用例](../probes/event_device_lifecycle.cpp)通过链接包装计数真实 ACL 调用，
创建、记录、跨流等待、销毁各 1000 次，每次返回码检查成功，最终退出 0。
这不是原来的主机模拟计数，也不代替长期显存泄漏画像。

训练复用设备方向 `proto_train_leg.py`，只适配私有输入/输出路径、初始化前绑卡和身份记录，
不改变训练算法。配置：Qwen3-Embedding-0.6B，FP32、50 步、每 Rank batch 4、seq 128、
AdamW、lr 1e-5，通信前三类对照全部正确。

## 真实故障与重建

在真实 AllReduce 校验通过后让 Rank 0 以 42 退出。torchrun 检测失败，监督器记录启动器退出 1、
无外层超时，停止旧组。将完整异常交 `runtime.translate_error`，得到
`L3_EXECUTION/replay`，`mapped=false`、`graded_by=message_hint`、
`is_grade_confident=false`。

由于旧通信组已失败，执行的是新进程/新通信组重建，不在损坏组内直接重放 collective。
同卡恢复探针 100 轮 1600/1600，启动器退出 0，未超时、未发现需强杀的残留进程组。
这是通信侧原型闭环证据，尚需监控方向确认；未宣称完成厂商精确错误映射、设备 reset 或模型检查点恢复。

## 设备冲突与恢复现场

之前独立 aclInit 返回 500000，驱动返回 87 RESOURCE_OCCUPIED。
驱动源码与设备/命名空间表确认：一个仍存活容器保留全部 16 个逻辑设备的挂载命名空间归属，
即便 npu-smi 显示无计算进程，新容器仍会冲突。

用户批准临时停止该容器后，同一训练环境 aclInit=0、device_count=2、aclFinalize=0，
完成了释放前后的 A/B。测试完成已确认无测试 Worker，训练容器恢复停止，
被临时停止的原容器恢复运行且 ID 不变。没有修改宿主驱动、重置设备或停止其他成员容器。
