# OneRec 双卡训练接入与通信验证

_补齐推荐模型真实权重训练入口；功能测试，不代替业务训练和默认基座验收。_

---

## 📋 本轮新增

基于公共分支 `f940196` 和设备原型 `3c62d59`，继续使用 910C v3 锁定镜像。开工时设备分支为 `2c0434e`，交付前复查新增 `0c59b95`：仅增加 P800 停任务/数据迁移记录，未修改本次消费的 runtime 实现。不重复申报设备方向的 Qwen 验证，也不将性能方向 OneRec 推理结果算作本方向训练成果。

新增 [OneRec 训练入口](../training/onerec_smoke.py)，使用组内共享的完整 `OpenOneRec/OneRec-8B` 权重，36 层、hidden size 4096、8,391,013,376 个参数全部参与训练。复用设备原型的选卡、同步、显存接口，以及本方向已有的逐张量/合并梯度平均逻辑；不使用 DDP，不缩小模型，不安装额外依赖或修改公共基座。

配置为 BF16、两 Rank、每端 batch 1、序列长度 16；先跑 3 步冒烟，再把 HCCL 两路径扩到各 50 步。梯度检查点启用，SGD 学习率 0.01、无动量。输入是固定种子生成的不同 token 分片；这用于验证前向、反向、梯度聚合和参数更新，不是推荐数据集训练，不报告收敛、推荐质量或稳定性能收益。选择无动量 SGD 是显存受控的功能入口，不等同于 AdamW 完整训练配方。

## 📊 实测结果

| 配置 | 训练主体 | 最终两端参数 | 退出/整体验收 |
| --- | --- | --- | --- |
| [HCCL 逐张量](../results/20261014-onerec-hccl/summary.json) | 双端各 3 步，梯度有限 | 399/399 张量 SHA256 一致 | 退出 0，CLOSED，通过 |
| [HCCL 合并梯度](../results/20261014-onerec-hccl-fused/summary.json) | 双端各 3 步，梯度有限 | 399/399 张量 SHA256 一致 | 退出 0，CLOSED，通过 |
| [FlagCX 逐张量](../results/20261014-onerec-flagcx/summary.json) | 双端各 3 步，梯度有限 | 399/399 张量 SHA256 一致 | SIGABRT，清理未完成，失败 |
| [HCCL 逐张量扩展](../results/20261014-onerec-hccl50/summary.json) | 双端各 50 步，梯度有限 | 399/399 张量 SHA256 一致 | 退出 0，CLOSED，通过 |
| [HCCL 合并梯度扩展](../results/20261014-onerec-hccl-fused50/summary.json) | 双端各 50 步，梯度有限 | 399/399 张量 SHA256 一致 | 退出 0，CLOSED，通过 |

三种配置每端均有 387 个参数张量发生更新；HCCL 两模式的最终完整参数哈希也一致。对照的是每个参数完整字节，不是少量元素抽样。汇总器同时检查启动器退出码、步骤数、完整参数量、梯度有限值、调用/载荷计数、参数哈希和通信组关闭状态；不会因为训练主体完成就忽略退出失败。

50 步扩展两端仍各有 387 个参数张量更新，两模式最终完整参数哈希也一致；对应 Rank 的两模式 loss 曲线最大差 `2.86102294921875e-6`。每端 50 步梯度 AllReduce 为逐张量 **19950 次**、合并 **50 次**，输入张量载荷同为 839,101,337,600 B。每配置本次只有一轮 50 步，没有独立重复样本，不推导性能提升或置信区间。

HCCL 合并梯度将每端三步梯度 AllReduce 从 **1197 次降到 3 次**，输入张量载荷均为 50,346,080,256 B，不代表链路实际流量。代价是结束时设备原型报告的 `used_mb` 从逐张量最大 36,716 增至合并最大 52,720，`allocated_mb` 均为 32,009；原型实现按字节除以 1024²，实际单位为 MiB，分别约 35.9 / 51.5 GiB。50 步两路径对应最大值 36,718 / 52,719 MiB。以上是结束时快照，不是峰值画像。后续应采用有界分桶，不能把整个 8B 梯度合并当成通用最优方案。

FlagCX 本轮没有观察到最终参数不一致，但清理阶段仍报 `free(): invalid pointer`。不能据此撤销此前 DeepFM 的失败记录，也不能宣称默认 FlagCX 路线验收通过。两模型、两精度、两优化器的结果不能直接归因为同一内核缺陷。

## 🔍 证据与边界

每个结果目录保留两端 JSON、启动器完整日志、命令及退出码。`initial_sha256`/`final_sha256` 为运行中从完整设备参数复制到主机计算的 SHA256，Mac 汇总不依赖通信后端。前三步未做吞吐重复采样，日志耗时包含编译、有限值检查等，不将其汇总为性能提升。

原权重从 27 号机 `/data_lib/models/OneRec-8B` 复制到本人共享测试目录，原文件未修改；11 号机使用同一共享目录。三片权重源/副本 SHA256 完全相同，见[模型与代码身份记录](../results/20261014-model-extension/provenance.json)。权重不上传 GitHub。

最初两轮使用只支持逐张量的入口，留档为 [实际测试源码](../results/20261014-model-extension/onerec_manual_tested.py)；之后仅增加 `--mode` 及对应分支、记录字段，第三轮执行合并路径；50 步扩展仅将允许的步数上限从 10 改为 50。所有轮次均使用相同聚合器。新增汇总与诊断测试 7 项，加上既有 32 项，共 39 项主机检查；主机测试不是 NPU 验收。

## 🎯 三模型后续安排

Qwen 保留设备方向及历史训练证据，不重复计新增；DeepFM 已有多轮数值对照，继续定位 FlagCX 时序与生命周期问题；OneRec 从未接入推进到真实权重双卡训练功能验证，下一步补长序列、有界分桶及多轮复测。三模型最新默认路线仍未全部验收，P800 目前仍仅完成环境准备；鉴于设备方向最新记录正在配合数据迁移，恢复前先确认迁移窗口，不擅自启动其容器。不因新增 OneRec 试验自动提高原任务表完成率。

## 🔧 复现

在核验锁定镜像、空闲两卡和权重身份后运行，输出目录必须全新。由外层启动器保存日志、退出码并实施超时；不使用退出绕过手段。

```bash
python3 -m torch.distributed.run --nproc_per_node=2 --master_port=29674 \
  dev/communication/training/onerec_smoke.py \
  --runtime-root /workspace/dev/device-context/prototype \
  --model-root /workspace/OneRec-8B --collective hccl --mode fused \
  --steps 50 --output /workspace/new-onerec-result
# 默认路线显式改为 --collective flagcx；不以 HCCL 替代验收。
```
