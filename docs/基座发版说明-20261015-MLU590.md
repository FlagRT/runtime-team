## 3. 运行配置与怎么起

**前置**：宿主驱动 6.2.x 线（实测 v6.2.29）。宿主无需安装 neuware —— 全部 MLU 软件栈在镜像内。

```bash
# 1) 挑空闲卡（无带卡容器独占，但勿干扰他人容器）
cnmon | head -40

# 2) 起容器（strict 核对 image id 与基线声明一致）
dev/lib/up.sh dev/images/cambricon-mlu-runtime/v1/demo --strict

# 3) 容器内执行一律经 shell（/opt/triton 只在经 shell 启动时进 PYTHONPATH）
docker exec -it flagrt-mlu-v1-demo-mlu2 bash -lc 'python3 -c "import torch, torch_mlu; print(torch.mlu.device_count())"'

# 4) 收尾
WORKSPACE_ROOT=$PWD docker compose -f dev/images/cambricon-mlu-runtime/v1/demo/docker-compose.yml down
```

**设备授予**：不用 `--runtime`、不需要 `--privileged`（寒武纪无容器 toolkit）；声明式授 18 个节点 ——
`/dev/cambricon_ctl`（缺它设备枚举失效）、`/dev/cambricon_gdr`、`cambricon_dev0..7`、`cambricon_ipcm0..7`；
另需 `--cap-add=SYS_PTRACE` 与 `--security-opt seccomp=unconfined`，并挂 `/usr/bin/cnmon:ro`。

**选卡变量**：`MLU_VISIBLE_DEVICES`（按授予顺序密集重编号）。demo 映射全部 8 卡 ⇒ 容器内逻辑号 == 宿主物理号。

## 4. 限制清单（各带删除条件）

| 编号 | 限制 | 规避 | 删除条件 |
|---|---|---|---|
| C-2 | `torch.mlu.get_device_capability()` 返回 `(5, 0)` ⇒ **FP8 与 MX 量化不可用**（厂商手册标注 FP8 需 ≥ (6,0)、MX 需 ≥ (6,1)） | 无（硬件代际约束）；量化方案避开 FP8 / MX，走 SmoothQuant 等 | 更换到 capability ≥ (6,0) 的卡型 |
| C-3 | `import triton` 必须先 `import torch_mlu`，否则报 `Failed to load the backend extension: mlu`；且 `/opt/triton` 只在经 shell 启动时进 `PYTHONPATH` | 先 `import torch_mlu` 再 `import triton`；容器内执行一律 `bash -lc`。不要用 `TORCH_DEVICE_BACKEND_AUTOLOAD=0` | 上游修正导入期副作用，或 torch_mlu 改显式注册 |
| C-4 | CNCL 走 MLU_LINK 片间互联，未加载 `libibverbs` / `libmlx5` ⇒ RDMA 未启用，集合通信结论只覆盖单机多卡 | 跨机集合通信不在现行结论覆盖范围；单机多卡不受影响 | 完成 RDMA 归因实测并给出可用配置（或确认平台不提供） |
| C-5 | `torch.mlu.Stream(priority=…)` 对区间 `(0, -3)` 之外取值静默接受、不报错 | 消费方按 `stream_priority_range()` 自行校验并回读 | torch_mlu 上游补参数区间校验 |

**另两条使用面约束**（非缺陷，属环境事实）：① 可用镜像档位由宿主驱动版本决定（6.2.x 线 → `neuware4.4.3` 档；
`neuware4.7.2` 档需宿主驱动 6.5.48），选档是本芯片的第一判据；② 宿主只装驱动、无 `/usr/local/neuware`，
一切验证必须在带卡容器内做。

## 5. 获取方式

公开 Harbor registry，**匿名可拉，无需凭据**：

```bash
docker pull harbor.baai.ac.cn/flagos-runtime/flagos-runtime-cambricon-neuware4.4.3@sha256:e55b420ee98e0fdef6c18a27b633d67b988ecef81a52a0fef5a0c6636c91d5c2
docker image inspect harbor.baai.ac.cn/flagos-runtime/flagos-runtime-cambricon-neuware4.4.3:2.2.0 --format '{{.Id}}'
#   预期：sha256:e887e0ca4333a27185817fb8fef6ce95d5d9220c5a9725641187d602cabeea96
```

按 digest 拉取后本地无 tag，`up.sh --strict` 以 tag 核对 ⇒ 另按 tag 拉一次（层已缓存，瞬时完成）即可建立 tag 到 digest 的映射。

## 6. 分发

不另做离线包：镜像在公开 Harbor 上按 digest 可拉，分发路径即 registry。
