## 平头哥 PPU

### 这个镜像是什么

平头哥 PPU（真武 ZW810E，x86_64）的 FlagTree 官方基座，训练（transformers DDP）与推理（镜像自带 vLLM 0.19.0+cu130）同底座：

| 层 | 内容 | 版本锚 |
|---|---|---发|---|
| L1 厂商基座 | BAAI·FlagTree 官方预构建镜像（公开 Harbor，被动继承，无本组配方层） | `flagtree-ppu-py312-torch2.10.0-sdk2.1.0-cu130-ubuntu24.04:202607-3.6-base` @ digest `sha256:50a906e6…`；内置 Python 3.12.3 / torch 2.10.0 / vLLM 0.19.0+cu130 / transformers 4.57.0 / PPU SDK v2.1.0（CUDA wrapper cu130）；集合通信 = 镜像内 `/opt/accl-p`（libpccl，NCCL API 兼容） |

镜像内 `/opt/vllm` 源码树无 `.git`（2026-10-15 探针实测）⇒ 无自证 commit 锚，版本主锚 = Harbor digest，辅锚 = pip 版本号。版本事实以 `dev/images/thead-ppu-runtime/v1/image.baseline.yaml` 为准；2026-10-15 带卡自检通过（`up.sh --strict` 起容器，`device_count=16`、单卡授予重编号生效、卡 2/3 matmul finite）。

### 怎么起

demo 运行环境：`dev/images/thead-ppu-runtime/v1/demo/`。仓根执行（机器 = PTG_0 / ai-server）：

```bash
ppu-smi | tail -24            # 挑空闲卡（0% util / 2MiB 显存）；无带卡容器独占
dev/lib/up.sh dev/images/thead-ppu-runtime/v1/demo --strict
docker exec -it flagrt-ppu-v1-demo-ptg0 bash
# 容器内环境核对（本 demo 的验收动作）：
python3 -c "import torch; print(torch.cuda.device_count())"              # 预期 16
CUDA_VISIBLE_DEVICES=2 python3 -c "import torch; print(torch.cuda.device_count())"   # 预期 1
# 用完收尾：
WORKSPACE_ROOT=$PWD docker compose -f dev/images/thead-ppu-runtime/v1/demo/docker-compose.yml down
```

### 已知限制

**无。** 本镜像自身不携带已知限制。两条环境事实（非镜像缺陷）已固化进 demo 规避配置：

| 编号 | 现象 | 规避方式（demo 已内置） | 说明 |
|---|---|---|---|
| — | `--network host` 下宿主主机名（ai-server）不在 DNS → torchrun/c10d rendezvous 静默挂 300s 后超时 | demo 已设 `extra_hosts: ai-server:127.0.0.1` | 环境事实；`mp.spawn` + `tcp://127.0.0.1` 路径不受影响 |
| — | 镜像写死 `NCCL_SOCKET_IFNAME=eth0`，本机真网卡是 bond0 → nccl all_reduce 报 `Bootstrap: no socket interface found` | demo 已覆盖 `NCCL_SOCKET_IFNAME=bond0` | 环境事实；自建环境须同样覆盖 |

### 必须设置与必不设置的运行配置

- **必设**（demo 已内置）：`NCCL_SOCKET_IFNAME=bond0`（覆盖镜像内写死的 eth0）。
- **选卡纪律（与昇腾相反、同 P800）**：无带卡容器独占，`docker ps` 只是共享机礼貌；`ppu-smi` 挑 0% 利用率 / 2MiB 显存的空闲卡，以 `CUDA_VISIBLE_DEVICES=<物理卡号>` 自律（demo 映射全部 16 卡使容器内逻辑号 == 宿主物理号；自建环境只授予卡子集时须写重编号后的逻辑号）。
- **设备授予**：声明式 `devices:` 授 `/dev/alixpu` + `/dev/alixpu_ctl`（缺 ctl 则设备枚举失效）+ 所用 `alixpu_ppuN`；不需要 `--privileged`，不需要挂宿主驱动（PPU SDK 在镜像内）。
- **机器环境注意（PTG_0）**：根分区 94% / `/data` 99%（勿写入）；docker 与大文件落 `/bmcp_lvm_fs`（11T）；宿主 `python3`=3.6 过老，跑 `dev/lib` 工具须 PATH 前置 `python3.11`（如 `export PATH="$HOME/.local/pybin:$PATH"`，已建软链）。

## 平台缺陷移交（不入本发版限制清单）

PPU 侧已定位的平台缺陷（退出期弱引用悬垂 SIGSEGV，根因在平台侧 `Py_FinalizeEx→_PyWeakref_ClearRef`，本组运行时层已规避、不影响正常结论）由 device-context 方向在其目录内跟踪并转厂商跟进；属运行时层职责外的平台事实，不入本发版已知限制清单。
