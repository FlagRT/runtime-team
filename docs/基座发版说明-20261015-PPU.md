平头哥 PPU（真武 ZW810E）发布物一件：**thead-ppu-runtime v2 = 派生镜像**（BAAI·FlagTree 官方基座 + 本组一层派生：一个 flagtree wheel 离线固化，同时提供 `triton` 3.6.0 与 `flagtree`；repro_status 🟢 functional-repro）。**现行生效版本 = v2**（2026-10-29 总组裁定，指挥台 ADR-0011）；v1 = v2 的基座层（Harbor digest 可拉，非废弃）。PPU 设备 API 走 `torch.cuda` 命名空间（`torch.xpu.device_count()==0`），选卡与多容器纪律同 P800 型（无带卡容器独占）。锁定声明 = `dev/stack.lock.thead-ppu.v1.yaml`（其 `lock:` 已指 v2）。

## 平头哥 PPU

### 这个镜像是什么

平头哥 PPU（真武 ZW810E，x86_64）运行时基座，训练（transformers DDP）与推理（镜像自带 vLLM 0.19.0+cu130）同底座：

| 层 | 内容 | 版本锚 |
|---|---|---|
| L1 厂商基座（v1，被动继承，字节不动） | BAAI·FlagTree 官方预构建镜像（公开 Harbor） | @ digest `sha256:50a906e6…`；内置 Python 3.12.3 / torch 2.10.0 / vLLM 0.19.0+cu130 / transformers 4.57.0 / PPU SDK v2.1.0（CUDA wrapper cu130）；集合通信 = 镜像内 `/opt/accl-p`（libpccl，NCCL API 兼容）；**不含 triton/flagtree** |
| L2 本组派生层（v2 增量，只做加法） | 一个 flagtree wheel（`flagtree-0.7.0+ppu.gite223f42c`，共享盘既有构建产物）经 `pip install --no-index --no-deps` 固化，同时提供 `triton` 3.6.0 + `flagtree` | wheel sha256 `b57daff7393972d9c5ff2487930caf2416d0cbd79d8f50b0fd6a5ca56c5378b4`；不升级/降级基座任何包、不装本组运行时 |

为什么需要这一层：vLLM 起服务前门控 `find_spec("flash_attn") and find_spec("triton")`，官方基座 triton 缺失 ⇒ 服务化腿必然起不来；固化后「拉起镜像即可服务化」，且该依赖成为镜像内声明事实（ENV-SPEC「外部依赖须声明」）。

镜像内 `/opt/vllm` 源码树无 `.git`（探针实测）⇒ 无自证 commit 锚，版本主锚 = image id + wheel sha256，辅锚 = pip 版本号。版本事实以 `dev/images/thead-ppu-runtime/v2/image.baseline.yaml` 为准；全新容器验收记录（真编 kernel / 服务化 / 现役容器判据 / 基线 check）见 `dev/images/thead-ppu-runtime/v2/assets/evidence/`。

### 怎么起

运行环境：`dev/images/thead-ppu-runtime/v2/env/v1/`（镜像版本 v2 下的环境版本 v1，ADR-0008 机制）。仓根执行（机器 = PTG_0 / ai-server）：

```bash
ppu-smi | tail -24            # 挑空闲卡（0% util / 2MiB 显存）；无带卡容器独占
dev/lib/up.sh dev/images/thead-ppu-runtime/v2/env/v1 --strict
docker exec -it flagrt-ppu-v2-env-v1-ptg0 bash
# 容器内环境核对（本环境的验收动作）：
python3 -c "import torch; print(torch.cuda.device_count())"              # 预期 16
python3 -c "import importlib.util as u; print(u.find_spec('triton') is not None)"   # 预期 True（v1 基座为 False）
CUDA_VISIBLE_DEVICES=2 python3 -c "import torch; print(torch.cuda.device_count())"  # 预期 1
# 用完收尾：
WORKSPACE_ROOT=$PWD docker compose -f dev/images/thead-ppu-runtime/v2/env/v1/docker-compose.yml down
```

### 已知限制

**镜像缺陷级：无。** 两条使用注意与两条环境事实如下。

⚠️ **两个会误判的版本标签**（实测）：

| 现象 | 正确判法 |
|---|---|
| `pip show triton` **无输出** —— `triton` 是 flagtree wheel 内部一段，无独立 `dist-info` | 判「装没装」用 `importlib.util.find_spec('triton')` 或直接 `import triton`，勿用 `pip show`/`pip freeze` |
| `flagtree.__version__` 自报 **3.6.0**（跟随 triton 线号），pip 元数据是 **0.7.0+ppu.gite223f42c** | 版本锚一律用 wheel 文件名/dist-info + sha256，不用 `__version__` |

两条环境事实（非镜像缺陷）已固化进运行环境规避配置：

| 现象 | 规避方式（env/v1 已内置） | 说明 |
|---|---|---|
| `--network host` 下宿主主机名（ai-server）不在 DNS → torchrun/c10d rendezvous 静默挂 300s 后超时 | `extra_hosts: ai-server:127.0.0.1` | 环境事实；`mp.spawn` + `tcp://127.0.0.1` 路径不受影响 |
| 镜像写死 `NCCL_SOCKET_IFNAME=eth0`，本机真网卡是 bond0 → nccl all_reduce 报 `Bootstrap: no socket interface found` | 覆盖 `NCCL_SOCKET_IFNAME=bond0` | 环境事实；自建环境须同样覆盖 |

### 必须设置与必不设置的运行配置

- **必设**（env/v1 已内置）：`NCCL_SOCKET_IFNAME=bond0`（覆盖镜像内写死的 eth0）。
- **选卡纪律（与昇腾相反、同 P800）**：无带卡容器独占，`docker ps` 只是共享机礼貌；`ppu-smi` 挑 0% 利用率 / 2MiB 显存的空闲卡，以 `CUDA_VISIBLE_DEVICES=<物理卡号>` 自律（运行环境映射全部 16 卡使容器内逻辑号 == 宿主物理号；自建环境只授予卡子集时须写重编号后的逻辑号）。
- **设备授予**：声明式 `devices:` 授 `/dev/alixpu` + `/dev/alixpu_ctl`（缺 ctl 则设备枚举失效）+ 所用 `alixpu_ppuN`；不需要 `--privileged`，不需要挂宿主驱动（PPU SDK 在镜像内）。
- **机器环境注意（PTG_0）**：根分区 100% 满（勿写入、git 写操作前先 df）；`/data` 99%（勿写入）；docker 与大文件落 `/bmcp_lvm_fs`（11T）；宿主 `python3`=3.6 过老，跑 `dev/lib` 工具须 PATH 前置 `python3.11`（如 `export PATH="$HOME/.local/pybin:$PATH"`，已建软链）。

## 平台缺陷移交（不入本发版限制清单）

PPU 侧已定位的平台缺陷（退出期弱引用悬垂 SIGSEGV，根因在平台侧 `Py_FinalizeEx→_PyWeakref_ClearRef`，本组运行时层已规避、不影响正常结论）由 device-context 方向在其目录内跟踪并转厂商跟进；属运行时层职责外的平台事实，不入本发版已知限制清单。
