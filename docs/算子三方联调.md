# 算子三方联调

> 一个**现成的测试模板**

---

## 1. 最核心的文件（就 3 个，都在 PyTorch-Plugin-FL 仓库）

路径：`tests/integration/ops/`

| 文件 | 是什么 | 怎么用 |
|---|---|---|
| **`template_op_test.py`** | 空白模板（自带 mm 默认配置，可直接跑） | **算子组复制改名**，填表即可 |
| **`test_mm_triparty_template_demo.py`** | mm 完整样例（模板怎么填的参考答案） | **三组对照学习**，先跑它 |
| **`README.md`** | 英文使用说明（仓库内给所有人看） | 全组 |

（`conftest.py` 是公共平台标记，不用动；同目录其它 `test_*_dispatch.py` 是仓库基线的老用例，不影响。）

## 2. 测试步骤

```bash
# 0) 进开发容器（如没启动：docker start flagos-fl-dev-910c）
docker exec -it flagos-fl-dev-910c bash

# 1) 进仓库（已挂载）
cd /workspace/PyTorch-Plugin-FL

# 2) 跑 mm 完整样例（三方联调验证）→ 期望 19 passed
/root/tf-venv-integration/bin/python -m pytest \
  tests/integration/ops/test_mm_triparty_template_demo.py -v

# 3) 跑空白模板自检（验证模板可复用）→ 期望 18 passed
/root/tf-venv-integration/bin/python -m pytest \
  tests/integration/ops/template_op_test.py -v
```

## 3. 新增一个算子

```bash
# 1. 复制模板改名为 test_<算子名>_dispatch.py
cp tests/integration/ops/template_op_test.py tests/integration/ops/test_<算子名>_dispatch.py
```
2. 填 `OP_CONFIG` 表：算子名、torch 接口、形状、dtype、精度阈值
3. 若输入结构不是"两输入一输出"，改 `_make_inputs`（多数算子不用动）
4. 在 `[Op Team]` 区块补算子特有边界用例（非连续输入、零尺寸、极端值、`out=` 别名等）
5. 跑 `pytest tests/integration/ops/test_<算子名>_dispatch.py -v`，全绿即完成

## 4. 验收标准 + 已踩平的坑

**验收定义**：某算子三块测试全绿 = 三方联调通过，可作为该算子"能用"的证据链。
