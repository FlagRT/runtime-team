### 怎么起

demo 运行环境：`dev/images/ascend-train-comm/v3/demo/`（docker-compose.yml + env.baseline.yaml，推理与训练共用一个容器）。仓根执行：


- `up.sh --strict` 按镜像基线核对 image id 后启动，容器名 `flagrt-v3-demo-910c`。
- `FLAGRT_MODELS_DIR` 必须指向实体目录（仓根 `models/` 是指向宿主个人目录的软链，容器内无法解析；npu1-11 为 `/home/xliu969/models`）。

- 用完收尾：`docker compose -f dev/images/ascend-train-comm/v3/demo/docker-compose.yml down`。
- 多项验证共用一个容器，以 `ASCEND_RT_VISIBLE_DEVICES` 分区（第二个带卡容器一律 EBUSY）；`dev/stack.lock.910c.v2.yaml` 同时规定带卡容器并发上限 3。

### 必须设置与必不设置的运行配置

- **必设**（推理腿）：`VLLM_FL_PREFER=vendor`（K-2）；`PYTHONDONTWRITEBYTECODE=1`（demo 设，避免宿主 checkout 出现 root 属主的 `__pycache__`）。
- **必不设**：`XPU_EVENT_KL3_ENABLE`（K-3）。
- `CUDA_VISIBLE_DEVICES` 刻意不设默认值——选卡是每次运行的纪律。卡选择纪律（与昇腾相反，勿照抄）：P800 **无**带卡容器独占（实测 9 容器并存仍可用），`docker ps` 仅是礼貌；用 `xpu-smi` 挑 0% 利用率 / 0MiB 显存的卡，以 `CUDA_VISIBLE_DEVICES=<物理卡号>` 自律；demo 映射全部 8 卡使容器内逻辑号 == 宿主物理号，自建环境只授予卡子集时须写重编号后的逻辑号；多卡训练须选同 NUMA 组的连续空闲卡（本机 NUMA0=卡 0-3、NUMA1=卡 4-7），卡 1 历史上反复被其他租户占用，优先避开。
- 设备授予：声明式 `devices:` 授卡 + `/dev/xpuctrl`（缺它 `torch.cuda.device_count()` 为 0）；不需要 `--privileged`，不需要挂宿主驱动目录（XRE 在镜像内）。
- 本机重建该镜像的环境前提：`/var/lib/docker` 余量约 12GB（该盘 99% 满，构建前先 `df -h` 确认）、flagtree 索引可达（访问须绕过代理）。
