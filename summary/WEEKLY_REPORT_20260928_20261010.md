## 一、本周进展

### 结论（一句话）

本期把统一原型做了**一次接口面补齐 + 一批隐性行为修正**，并在 910C 上完成**全量复跑 20 项全绿**；
验证口径同时从「抽样用例」升级为「**逐条响应审计**」。对外接口 **28 → 46**，**严格只增、零破坏性改动**。

### 1.1 接口面补齐：新增 5 个接口分组

| 分组 | 补了什么 |
|---|---|
| **内存句柄** | 句柄式申请/释放 + 跨流内存保护（`record_stream`） |
| **设备上下文** | 生命周期四件事 + **只读观测**：把「上下文归谁管」写进返回字段，上层换芯片不必写分支 |
| **契约不变式 I1–I4** | 把「**声明过的能力 ⇒ 必有公共入口**」变成**自动守住的判据**，而不是靠人工核对 |
| **流优先级** | 能力键拆成**三把钥匙**（能读范围 / 能设置 / 能回读）+ 四道约束（未声明即报错、越界即报错、创建后强制回读、空值逐位不变） |
| **流所有权与释放** | 显式释放 + 所有权查询 + 使用前可用性检查（杜绝「在已释放对象上继续用」） |

- 对外出口 **28 → 46**（新增 18 项，**移除 0**）—— 既有调用方不需要改任何一行。

### 1.2 行为修正 8 处（全部属于「看起来通过」的隐性错误）

这类错误的共性是：**记录齐全、流程走完、验证全绿，只有交叉核对才发现结论是假的**。两处影响最大：

| 修正 | 不修的后果 |
|---|---|
| 无错误码表时**误用他厂码表**定分级 | **误触发最贵的设备级重建**（把一次参数错误升级成整设备重置） |
| 句柄回收后**被 id 复用**，越权销毁了不属于本层的流 | 破坏厂商自身的流，故障在下游才暴露 |
| 其余 6 处 | 恢复返回体取值域不可判 · 永久性参数错误被反复重放 · 降级时三个字段自相矛盾（把保守推断冒充成定论）· 能力字段缺失 · 有界同步实际不有界 · 统一错误对象不可 `raise` |

### 1.3 流控制两条链路打通（910C 真机）

- **流配额**：实测真实上限 **1979**（建满 1979 成功、第 1980 条被拒并给出明确错误码）——「配额」第一次有可复算的数字，不再是估算。
- **流所有权 / 释放语义**：探针 **6 通过 / 0 失败 / 2 如实跳过**（跳过项写明理由，不计入通过）。

### 1.4 设备级恢复：从「单进程」到「多卡多进程」

**3 进程 × 30 轮**，每轮轮换一个进程当「恢复者」真重建设备，其余进程持续同输入计算并校验结果：

- 恢复者 **30/30** 轮重建成功、返回契约五键齐全；
- 其余进程 **逐位相同**（不是容差近似）⇒ 证明「未被波及」；
- **零失败、零异常**，全程 11.0 s。

这是「某卡故障 → 设备级恢复」这条链**第一个具备生产级形态**的证据（此前只有单进程证据）。

### 1.5 验证口径升级：抽样 → 逐条

- 把接口约定承诺的**每一个** API 拆成 **78 项**逐条真机调用（此前 39 项）：910C **73 通过 / 0 失败 / 5 如实跳过**（跳过 = 该实例确实不具备，**不是缺口**）。
- 每条判据都配**注入式非空转验证**（故意注入缺陷，证明判据真的会失败）：**34 条全部抓到，0 条漏检** —— 杜绝「判据长期不报错 = 没问题」的假象。
- 顺带发现并修复 **2 处「实现了但没对外导出」**的缺口（内部可用、外部拿不到）。

### 2.2 复核过程暴露的一个取证纪律问题（已记入流程）

复核时一度读不到算子库里的关键判定逻辑，差点误判成「上游删了」。原因是**网络抖动导致文件下载被截断**（拉到了不完整文件）。

⇒ 已固化：**凡远程取证，必须校验完整性**（字节数 + 关键行比对），否则「内容变了」与「没下全」长得一模一样。这与本层一直在防的「看起来通过」是同一类错误。

| # | 问题 | 现状 |

### 2.4 初步设计思路

> 原则不变：**新芯片 = 按规范新建一个实例**，只迁规范、方法与框架代码，**不迁既有实例的实现与结论**。

1. **先解决「在哪跑」，再写代码。** 按既有的环境普查七项出报告，**第一件事是读宿主驱动版本**（它决定档位），第二件是读设备工具的原始输出 —— 镜像选型放在这之后，而不是先挑镜像。
2. **形态判定放在最前面且用实测。** 复用 CUDA 命名空间的结论目前只是间接证据，**必须**用「设备能否枚举 + 设备名字符串 + 命名空间归属」三项直接确认；同时把**集合通信后端名**探出来（探不到就报错退出，**绝不兜底** —— 兜底会静默退化成纯 CPU 通信，训练照样跑完还掉 loss，比失败更糟）。
3. **依赖与镜像按「驱动优先」定档**，并把档位作为结论的**限定条件**写进每一份产出（同档可比、跨档不比的纪律沿用）。
4. **验证路径沿用既有顺序**：离线自检（无需设备）→ 一致性用例 13+6 → 多流基线 → 逐条职责审计 → 训练腿/推理腿 → 服务化。**新实例从第一天就带非空转验证**，不补作业。
5. **跨厂商通信这条线单独标风险**：统一通信库未覆盖该芯片，能否用、以什么后端名用，**先实测再下结论**，不作为初步接入的验收项。
